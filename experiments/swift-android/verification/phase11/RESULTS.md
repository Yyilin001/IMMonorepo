# 第十一阶段：消息回复、转发与表情回应

2026-11-12，延续 `codex/swift-android-feasibility`。Android 复用现有 Swift 发送、转发计划和表情回应服务，未引入独立 Kotlin 业务实现。Swift 改动限于 Android 共享门面及组合运行时，iOS 原有调用路径保持不变。

## 已实现

- 对单条消息发送文本回复，回复正文和引用交给既有发送服务冻结、持久化、交接及恢复。引用预览由 Swift 按当前授权读取，随原文编辑刷新；撤回或失效后隐藏原文。点击有效引用可定位原消息。
- 将单条文本或附件消息转发至一个已有会话，目标会话支持分页选择。仅传源身份、选定版本和目标身份，原正文、媒体引用、计划指纹和子操作均由原 Swift / 服务端合同处理。源版本已变化时拒绝，不自动替换成新版本。
- 六种常用表情回应入口，以及对所有已同步回应的本人添加/移除操作。共享 SQLite 提供计数和本人状态，既有 Swift 服务合并未冻结目标、获取版本、提交及恢复。界面不预先改写人数，未决操作另行显示。
- 显示转发成功、拒绝、取消和未决数量，以及回应/转发的继续确认和取消剩余转发入口；每类最多 50 项。账号退出排空准备、观察、执行和平台 I/O，账号切换不复用旧会话、草稿或操作列表。
- 登录后的参数/版本失效显示内容或权限变化提示，避免提示用户检查登录信息。
- 修复回归中发现的自动已读上报与用户操作竞争：上报单独维护任务状态，不再禁用发送/编辑按钮；后台或所有者关闭时取消并排空，返回结果校验账号代次，防止旧任务恢复已退出账号的页面。

## 真实后端验收

使用独立 PostgreSQL、HTTPS 和 TLS 网关，API 31 arm64 Android App 从 `MainActivity` 登录开始。另一共享 SDK 客户端与 App 建立好友和群组，用例覆盖：

- 回复的双方同步与引用定位；编辑原文后预览更新，撤回后预览不可用且回应清空，禁止继续回复/回应撤回消息。
- 两个用户对同一消息添加 👍，人数达到 2；App 移除自己的回应后人数为 1，对端本人状态保留。
- 文本转发到群组后生成独立消息并保留转发标记；使用旧源版本提交转发被共享 SDK 拒绝。
- 16 KiB 文件消息转发后，由无源文件缓存的 App 实际下载、导出，内容与源文件逐字节及 SHA-256 相同。系统文档选择器返回真实文件 URI，由 instrumentation 注入；其后的文件 I/O、JNI、Swift 下载、HTTPS 和服务器均真实执行。
- 断开 App 实时 TLS 后提交回复、🎉 回应和转发，关闭完整客户端所有者并重开。恢复后回复引用正确、回应计数为 1、目标群共三条转发消息且各操作不重复。
- 切换第三账号后消息及操作列表隔离，结束时客户端、JNI 操作、HTTP 和 TLS 句柄全部归零。

最初附件校验误等“原发送者创建下载任务”；共享资源中心已有相同内容缓存，会直接返回本地可读结果。验收已改为无该缓存的 App 下载导出。另一次初始会话列表点击未命中后，新用例及第十阶段回归改用 Compose 点击语义定位指定控件，并等待对应端的消息/撤回投影，避免列表排序、键盘动画和跨端同步时序影响断言；所有业务操作仍经过真实页面事件与 ViewModel。

第五阶段基础聊天回归也在断线后输入并点击发送时超时；保留[首次失败日志](messaging-initial-touch-timeout.txt)。仅将该测试的发送点击改为 Compose 点击语义并断言控件可用后，同一 App APK 的完整用例通过；没有放宽业务断言。

服务端只读 SQL 独立核对两条回复均引用原消息、三份转发计划全部收敛并生成三条不同消息、四条回应操作回执已提交；转发附件保有有效引用，状态为 available，大小为 16 KiB。

最终隔离后端的 HTTP 汇总包含调试或回归请求，不能用总次数代替单条消息的操作次数；独立 SQL 只筛选最终第十一阶段账号和房间。

## 复现与范围

```sh
python3 experiments/swift-android/build_probe.py --reuse-capabilities --shared-sdk
# 等 native 构建完整退出后再打包。
python3 IMV2/scripts/verify_v2_isolated_native_account.py --hold-seconds 900 --resource-part-uploads
python3 IMAndroid/scripts/verify_shared_sdk.py --phase 11 --serial <owned-api31-emulator> --endpoints <isolated-root>/test-endpoints.json --output <output>
# 同一后端和 APK 回归 --phase 10 / 9 / 8 / 7 / 6 / 5。
```

本阶段限 API 31 arm64 模拟器。恢复验收为完整客户端所有者关闭重开，不是操作系统强杀或断电；断开的只有实时 TLS，转发和回应 HTTP 仍可能在关闭前完成，因此不宣称模拟了所有 HTTP 请求结果丢失窗口。相关持久状态机另有 Swift 回归。

当前回复仅支持非空文本，转发为单条、单目标；未接入回复附件、多选批量、多目标或合并转发、完整自定义表情选择器。来源仅显示转发标记，不提供跨房间原消息跳转。重试和取消入口已接入，但没有逐项新增转发部分失败、处理中取消、HTTP 丢响应故障注入或大群回应压力验收。
