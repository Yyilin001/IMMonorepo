# 第十七阶段：统一联系人和群组业务门面

状态：完成。共享层与领域单测 62 条、iOS 单测 200 条、iOS 真实后端功能 8 步及范围清理 2 步、Android 联系人/群管理与邀请/禁言 2 组验收通过。原生 Swift 两个后端用例通过；一次中间等待超时及成功复验见 retained-failures.json / native-backend.json。普通 Android Debug/Release 构建与 lint 通过，测试后端和本阶段设备已清理。

## 实现

- `V2ContactService`：联系人分页/窗口、黑名单、公开账号解析、关系提案与重试、持久化私聊及建房前消息。
- `V2GroupService`：群目录、成员目录、公告/角色权限读取、建群恢复、成员/角色/所有权/解散、邀请审批和成员禁言管理。
- `V2SharedSession` 按账号数据库缓存两组服务，并在账号或数据库关闭前回收。子服务共用 `V2DirectoryLifetime`，执行器和准备任务也受相同生命周期约束。
- iOS 的原生适配器、联系人/群目录数据源与邀请页面均注入门面；Android `SharedSocialGroups` / `SharedCommunity` 调用同一服务，Kotlin 保持绑定和 UI 职责。HTTP/TLS 契约、底层持久化命令身份和确认修订保持不变。
- 每个观察者独立订阅，取消窗口不会终止兄弟订阅；关闭账号等待仍在回收的生产者、物理查询以及 iOS 查询协调器完成，再释放数据库。成员读取在网络返回后再次校验本地读取授权。

## 验证范围

单测覆盖独立联系人游标和订阅、旧句柄失效、另一激活代的确认拒绝、查询中途撤权、重复分页游标、取消窗口后的生产者回收和查询协调器单次清理，并运行已有门面、会话所有权与相关领域测试。

真实后端为独立 PostgreSQL、账号 HTTPS 服务、边缘服务和原生 TLS 网关，非 mock，未使用生产账号。原生 Swift 宿主验证关系/群管理、物理断线、冷恢复和第三账号隔离；Android API 31 安装实际验证 APK，从 MainActivity 验证联系人、权限、群管理、邀请与禁言。iOS 使用两台本阶段创建的 iOS 18.5 模拟器运行真实注册、建群和邀请审批页面。

具体测试数、APK 指纹、后端结果、符号兼容和清理状态见本目录 JSON。既有 SDK 五个模块公开 API 清单需与第十六阶段完全一致；新增门面记录单独列于 native-swift-api.json。
