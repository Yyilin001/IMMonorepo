# 第十八阶段：统一资料、头像和资源业务门面

状态：本阶段实现及主流程验收完成。iOS 18.5 资源场景 6 个功能步骤与 3 个作用域清理步骤全部通过；后台专项与 iOS 27 的限制按下文单独列出。测试设备已删除，11 组隔离后端均已停止，临时诊断保留。

## 实现

- 账号级 `V2ProfileService` 提供授权资料展示、投影查询、备注/群昵称和自身资料命令。页面分别持有 activation；独立观察、修订冲突和头像租约继续由既有领域服务负责。
- `V2ResourceService` 统一上传准备、附件消息冻结、发送交接、取消、下载和授权头像字节读取。资源目录、导入、传输恢复与缓存作为已有业务子服务复用。
- 原 iOS 群头像业务移入 `V2GroupAvatarService`，包含授权、修订检查、资源复用、持久化命令和失败处理。iOS 适配器只转换页面值，Android 的 Swift 绑定调用同一服务。
- `V2SharedSession` 按账号数据库持有并回收服务；退出时排空操作和观察者，关闭上传、下载、资料仓库后才释放数据库。未新增 Kotlin 业务实现。
- iOS 保留原生 Swift 调用、系统后台传输协调器和现有页面行为。旧构造入口仍供兼容宿主及已有测试使用；生产组合注入共享门面。

## 验收夹具修正

后台上传授权合同已采用 `scope.part.number`，旧 Python 观察器读取 `partNumber` 会把合法后台请求误计为前台请求。本阶段对齐当前合同，并增加两条观察器测试；不改变生产传输策略。

上传端可复用原文件，旧下载验收不能强制它再发 GET。严格后台上传在独立用例中已有一次通过；后续模拟器不进入挂起的失败单独保留。资源功能专项使用明确命名的真实上传准备步骤，再清理该测试安装 scope，经真实 UI 登录重建后验证手动 Range GET 下载，最后冷启动确认缓存复用。准备步骤不宣称验证上传时挂起，也没有放宽独立后台上传用例的断言。当前手动下载的持久化前台需求会选择 Range GET，专项验证真实 206 响应及原件校验；不把该结果算作后台下载挂起通过。原后台下载用例仍保留原断言，生产策略没有改变。下载字节观察器也对齐当前账号 `.background` 收件箱和资源日志绑定的 UUID 文件，并验证未绑定或损坏文件不能作为证据。页面的完成断言跟随现有“查看文件”入口。未通过改动产品缓存策略制造测试请求。
