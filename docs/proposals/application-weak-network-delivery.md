# 应用级弱网交付摘要

更新：2026-09-28。当前目标是整个 App 的统一弱网架构；不保留历史兼容层。按用户最新要求，本次单机连接恢复验收规模为 **1,000**。业务改动集中完成后统一验证，不逐项重复执行未受影响测试。

## 当前交付

- 公共持久工作装配覆盖 32 个 kind：30 个 App handler 和 2 个资源专属引擎。原身份、固定截止、永久回执、未知结果恢复与关闭证明贯穿执行和用户处置。
- 账户、资料、偏好、社交、建群、群管理、邀请、消息及资源入口已实施相应持久恢复和页面状态接线；旧命令 lane 与旧消息写 wire 已退役。完整入口登记见[操作清单](application-network-operation-inventory.md)。
- 待处理发送支持活跃项优先、终态历史分页、精确 ID 重试/取消；服务器受理后在本地投影到达前显示等待同步，不能当作送达或重新发送。
- 资源上传、下载、后台桥接及本地参考 provider 已有装配；外部存储/CDN适配与真机系统行为不计为已交付验收。

上述描述是当前实施范围，不代表所有故障交错都已验收。限定源码核对确认公共 handler 与资源专属引擎对应全部 32 个 kind，后台任务接管、资源恢复观察和发送分页路径已装配；未发现这些核查范围内的新增确定接线缺口。详细依据见[实施进度](application-weak-network-progress.md)和[回归范围](application-weak-network-regression-scope.md)。

交付核对另删除了未注册的旧全局消息恢复路由、客户端失实登记及仅服务于该入口的 Core 请求/结果、Actor 命令、RoomRef 方法和旧恢复 store。当前按房间恢复的接口、共享受理结果和永久关闭判别逻辑保留，未修改永久证明表。这次删除发生在下述容量验收之后；静态引用检查及 Server 全产品生产编译通过（38.27 秒，日志 `/tmp/weak-network-global-recovery-removal-server-build.log`），不把之前的日志记为删除后的行为复验。未重跑容量或业务套件。
