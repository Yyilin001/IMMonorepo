## 1. 产品范围

统一管理消息图片、视频、音频、文件、个人头像和群头像的本机文件、传输与存储。先交付聊天资源管理，首版不建设独立网盘、跨全部会话的云端全文资源搜索、转码集群或永久离线授权。

入口沿用登录后的统一导航：

- 我的 → 文件与存储 → 资源目录、传输任务、存储管理。
- 会话详情 → 聊天文件：同一目录组件加会话过滤。
- 消息附件 → 详情/预览 → 下载、分享、保留本机、查看来源。

图片/视频使用网格，文件/音频使用统一 List。组内连续行与分隔线，小标题，sheet 完成按钮在右侧。任务图标具有状态颜色及文字/无障碍说明。不会新增主 Tab。头像参与存储统计，在独立业务上下文管理，不混入聊天文件列表。

全局目录明确标注“本机已索引”；会话目录联网补齐其可见历史。首次打开、切 Tab、进后台再回来均先呈现本地已有数据，不插入假记录，不等待网络再决定是否显示页面。

## 3. 架构与唯一事实来源

调用方向：`View → MainActor Store → 账号 ResourceCenter → 领域执行器 / GRDB / FileStore / Scheduler → API 与 URLSession`。

- 每个账号 incarnation 独立目录、任务、文件与授权；页面只持有快照和路由身份。
- GRDB 保存目录、引用、保留意图、发送依赖和 canonical journal。上传、导入、下载各保留唯一合法状态机，共同派生只读传输列表；不再建第二份可写总任务表。
- FileStore 是受管文件发布、借用、退役和删除的唯一所有者。页面不长期保存裸路径。
- Scheduler 统一控制实际上传/下载名额，前台和系统后台均计入。取消发出后，实际 I/O 结束才释放名额、文件借用和预算。
- 上传执行器不能自行决定消息是否重发；消息及头像结果由各自原操作确认。
- ResourceCenter 关闭时停止准入并等待真实任务排空。旧账号回调不能写入新账号，即使 userID 相同也要验证 incarnation。

身份分开：`LocalAssetID` 为导入原件，`ResourceKey(home, mediaID)` 为服务端资源，`VariantKey` 为原件/衍生版本，账号内 `hash + size` 为已验证字节。URL 只是短期传输许可，不是任何一种资源身份。相同 hash 不意味着相同业务权限。

## 4. 用户操作对应的完整链路

### 选择与发送

选择照片/文件 → 受控流式复制及校验 → 持久原件与 LocalAsset → 同库事务冻结 SendIntent 和依赖 → 立即出现本地消息 → 排队上传/导入 → 资源 ready → 提交原消息操作 → 确认结果后按依赖释放原件。

离线也能创建本地聊天、草稿和待发送气泡。失败不丢唯一原件。ACK 丢失或提交结果未知时查询原操作，不新建另一条消息。服务器导入也必须沿用同一原操作标识。

### 下载与使用

从可见消息/头像取得访问上下文 → 查账号内已验证缓存 → 必要时申请短期下载计划 → 版本绑定的 Range 或系统下载 → 校验总长度及 SHA-256 → 文件发布和目录更新 → 返回 lease 给预览/分享。

206 核验区间；200 按整文件处理，不能追加旧 partial；412 重新核验版本及授权；416 不能直接当成功。地址过期只刷新计划，不让目录和消息失效。共享物理文件可复用，但每个读取方独立验证访问资格。

### 暂停、重试与取消

以阶段派生合法动作，不允许所有任务无条件展示四个按钮。

| 情况 | 行为 |
| --- | --- |
| 下载传输中 | 请求暂停/取消，排空实际写入后更新终态；继续重新鉴权、核验同版本 |
| 整文件 PUT 上传 | 能停止并保留源；继续可能整文件重传，不能展示“从已传字节续传” |
| 冻结消息依赖的上传/导入 | 通过消息所有者取消整个未提交发送意图；界面明确说明涉及整条消息，不能删掉其中一个附件改变冻结载荷 |
| 头像依赖 | 通过个人/群头像领域所有者处理，不直接删除源或覆盖原操作状态 |
| 已提交或结果未知 | 确认原结果；只有有证据证明未提交才允许创建替代操作 |
| 多个消费者共享下载 | 退出一个页面只撤其需求；管理页取消须重新检查所有依赖 |

管理命令执行时再次验证当前状态，防止按钮展示后发生提交竞争。不可逆的服务端业务事实不能靠本地“已取消”覆盖。失败项支持按合法能力批量重试，不进行无限循环重试。

### 清理与保留

先生成清理预览，再执行并重新验证：跳过借用中、用户保留、待发送原件、结果未知依赖及活跃任务。清理仅删除可重建本机字节，不删除消息或 OSS 正式对象。部分成功应给出实际释放量和跳过原因。

“保留本机”是逻辑版本意图；文件被系统清除时仍显示保留意图和需下载状态。它不延长服务端权限。撤权后停止受保护内容读取，不能用本地文件绕过授权。

## 5. 存储、服务端与策略

持久目录放账号数据库、唯一待发送原件和保留文件；Caches 放可重建下载与缩略图；后台传输最小副本/收件放独立 AFU 范围，不降低正式账号库和全部文件的保护等级。退出账号统一退役所有根。文件系统变更采用操作 journal + 启动对账，不能假定 SQL 回滚会撤销文件 rename。

默认参数作为可配置产品初值：缓存 512 MiB，待发送原件 2 GiB，临时预算 512 MiB，保留文件 2 GiB 提醒；不是预分配，也不是超额强删授权。准入按复制、后台副本、partial 和发布期间可能同时存在的文件计峰值，并处理实际 ENOSPC。可用空间安全线须结合真机测量调整，不能只依赖当前 16 MiB 初值。

总字节任务初值 4、上传最多 2、下载最多 2；交互 > 用户排队 > 自动下载，同时采用公平调度防止后台永久饥饿。实时进度是执行器观测值，界面合批更新至最多约 4 Hz，不伪造百分比。完成记录最多 500 条/30 天，淘汰展示历史不能删除仍被业务引用的恢复事实。

默认仅非昂贵、非受限 Wi-Fi 自动下载图片，单项 10 MiB；视频/音频/文件由用户开启。手动下载受明确的蜂窝设置限制。自动失败最多 5 次退避，尊重 Retry-After；权限、完整性、空间问题转待处理。网络变化停止新的不合规准入，已运行原生任务单独处理。

服务端在现有资源合同上补齐或核验：描述与不可变版本/校验值、可见会话资源分页、短期授权、导入原操作查询/取消、幂等上传完成及后台资格。会话分页使用稳定排序键和快照上界，撤权后旧游标不得继续泄露内容。OSS 保持私有，客户端不保存 AccessKey，签名 URL 不进入日志和业务数据库。

## 7. 测试与交付门槛

- 单元：身份、合法状态转换、动作能力、预算、退避、稳定排序与权限边界。
- GRDB + 真实临时目录：事务和文件操作各中断点、借用与清理竞争、同任务恢复、取消/提交竞争、账号关闭/迟到回调。
- HTTP：真实状态码、Range/版本变化、短期 URL 过期、超时/断网、校验错误；明确区分模拟 transport 与真实 OSS 证据。
- UI：本地目录立即显示、媒体筛选、任务控制、来源定位、清理预览、偏好保存；覆盖深色、大字体和 VoiceOver。
- 真机：首次解锁前、首次解锁后再次锁屏、系统终止并回接、用户强退后重新打开、切换账号、蜂窝与低数据模式。
- Release 性能：指定设备与 1 万条目录数据，首个本地可用快照 p95 目标 ≤ 200ms；50 条首屏无主线程数据库/文件 I/O 或原图解码；反复打开关闭不持续增长任务/内存/磁盘。以上为待测目标。

不考虑兼容性：统一修改合同与新建库 schema，删除旧入口、旧模型与双写；不引入旧字段 fallback。不兼容版本明确拒绝，不猜测解析。环境重置须列出具体测试库和目录，不把“不兼容”解释成可任意清除手机、账号或 Bucket。发布前保存可恢复的配对构建和环境快照，破坏性 schema 变更不能只回退二进制。

## 8. 官方资料与工程取舍

- [Apple 后台文件传输](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background)：稳定少量 session、系统回接和下载临时文件接管。项目据此保留原生桥接与收件阶段，而不让页面拥有传输。
- [Apple 存储与备份](https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup)：按是否可重建选择存储位置；据此区分唯一原件、保留文件与缓存。
- [Apple 后台 session 生命周期](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:))：系统终止后以同一标识回接；用户从多任务界面强退会取消后台传输，须再次启动后恢复。因此“退出页面继续”和“强退后继续”必须分别验收，不能向用户承诺后者。
- [Apple Photos picker](https://developer.apple.com/videos/play/wwdc2022/10023/)：选择项仍需异步加载；大资源通过文件表示导入，临时来源及时复制进受管目录。项目的 `V2PhotoLibraryImage` 已使用 `FileRepresentation`；后续视频/批量文件继续沿用受管导入而非把全部原件同时读进内存。
- [OSS GetObject](https://help.aliyun.com/zh/oss/developer-reference/getobject)：Range、Content-Range、If-Match/412。客户端必须核验响应，不把任意返回体追加到 partial。
- [SQLite WAL](https://www.sqlite.org/wal.html)：并发读取不消除单 writer 约束；进度合批、短事务，目录与发送依赖放同库事务。

资料检索轮读取了上述官方页面；Apple 页面提供的 Markdown 正文通过官方地址获取。并发数、额度、页面结构和阶段拆分是结合项目的设计选择，不是官方强制值。该轮仅修订规划，后续实现及运行验证另见完整设计和实施记录第37节；尚未部署或删除用户数据。

## 9. 数据合同与代码落点

以下按当前类型和表组织收敛，不另建一套平行资源系统。各表创建语句和 API 客户端/服务端同时修改；不写旧字段 fallback。

| 事实 | 唯一身份与必要字段 | 当前落点 / 目标约束 |
| --- | --- | --- |
| 资源描述 | `ResourceKey(home, mediaID)`，revision、类型、名称、长度、SHA-256、服务端状态、宽高/时长 | Core `ResourceDescriptor` 与 `v2_resource_entries`；ready 必须有可信校验值。已有宽高/时长字段不等于生产链路已经可信填充 |
| 不可变字节版本 | `VariantKey`，checksum、length、variant role | Core `ResourceVariant`、`v2_resource_variants`；描述修改不能悄悄替换相同版本字节 |
| 业务引用 | message/room/attachment 或 profile/group/avatar revision | `v2_resource_references`；消息同步、编辑、撤回与目录引用更新同事务；头像引用继续按所属领域补齐 |
| 本地原件 | `LocalAssetID`、用途、受管文件身份、依赖持有者 | 本地 asset journal 与 FileStore；发送前持久化成功，页面销毁不删除仍有依赖的原件 |
| 本地物理文件 | fileID、checksum、length、位置、校验/退役状态、访问时间 | `v2_resource_files`、consumers/pins/operations；不持久化任意外部绝对路径；SQL 与文件操作用 journal 对账 |
| 传输恢复 | 原 upload/import/download jobID，原 operation/session、nextAction、owner、attempt、retryAt、取消/暂停意图 | 既有三个 canonical journal；管理页只查询联合读模型，不反向写一张“总任务状态表” |
| 保留与偏好 | variant retention intent、类型/大小/网络策略、容量政策 | `v2_resource_retention_intents` 及 policy 表；设置写入成功即本地生效，重启后保持 |

服务端会话目录已有 `POST /v2/rooms/:roomID/resources/query`，继续补齐真实授权、稳定游标和撤权竞争测试，不新增重复路由。上传/完成/查询/取消沿用现有合同；若需扩展状态与 capabilities，先改 Core，再改服务端，再改 ClientKit，最后接页面。尺寸和时长由可信处理链核验后进入 ready 描述，不能把客户端自报值直接当可信事实。

页面实际分工：

- `IMApp/.../Resources/V2ResourceViews.swift`：入口与目录，复用统一导航；`V2ResourceLibraryStore`：查询、筛选、分页、不可变快照。
- `V2ResourceTransferView/Store`：任务列表与确认流程；动作只来自能力表，点击时在事务中重新验证。
- `V2ResourceManagementService`：App 预览、缩略图、分享及来源导航的适配；不另起恢复循环。
- `IMV2ClientKit/.../Resources/V2ResourceCenter`：账号命令与订阅；GRDB 保存事实，FileStore 管字节，现有执行器负责实际 I/O。
- `V2AppRealtimeRuntime`：在账号建立时装配，在账号关闭时停止准入、排空并退役；打开管理页不创建第二个运行时。

## 10. 完整动作能力表

| 操作对象 / 状态 | 用户动作与成功标准 | 不应发生的副作用 |
| --- | --- | --- |
| 本地选择尚未冻结 | 移除选择，最后消费者释放后回收 | 不影响其他草稿或已冻结消息 |
| 准备中的消息附件 | 预览涉及的整条消息数量，确认后事务取消父意图；沿原资源操作确认取消 | 不重组冻结载荷，不创建第二条消息，不恢复父意图 |
| 上传暂停 | 保存用户暂停意图，停止实际 PUT 并排空；保留源与原会话事实；继续先查询原结果再申请合法传输计划 | 不将 Task.cancel 当远端取消成功，不承诺整文件 PUT 的字节续传 |
| 服务端导入暂停 | 暂停本机后续调度；如无服务端 suspend 能力，明确“暂停本机跟进，服务器仍可能处理”，或不展示暂停按钮 | 不将停止轮询写成服务器停止复制 |
| 取消确认失败 | 显示“取消待确认”并进入需处理；“继续确认取消”重置有界确认预算，保留 cancellationRequested、原 ID 和已取消父意图，尊重 retryAt | 不走普通重新上传/导入路径，不清掉取消意图，不越过仍有 owner/原生任务的 I/O |
| 消息已提交、结果未知 | 查询同一 operation，显示“正在确认”；获得权威结果后更新 | 不生成新 operation 猜测补发 |
| 头像任务 | 交给 profile/group intent 所有者；管理页明确作用于头像设置 | 不绕过已冻结头像结果或仍待群决策的引用 |
| 下载暂停/取消 | 暂停保留合法恢复事实；取消清理不再使用的 partial；均等待写入者真实退出 | 不删除正在预览/分享或由另一个消费者使用的文件 |
| 下载重试/继续 | 同 job 重新验证权限、版本、网络政策，交互优先级重新准入 | 不把过期签名 URL 或旧校验值当永久有效 |
| 保留本机 | 落持久保留意图，缺字节时显示需下载；取消保留后按缓存政策管理 | 不等同删除消息、撤回或无限期权限 |
| 批量动作 | 显示可执行/跳过数量，每个对象执行时再验证，反馈部分成功 | 不把一个失败项写成整批成功，不让批量绕过单项限制 |

暂停、取消和重试属于不同命令。上传的“停止本次尝试”与“取消原服务端资源操作”必须分开，否则恢复时可能继续发送用户已撤回的消息。

### 13.3 官方资料核验与项目取舍

- [Apple 后台下载](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background)：后台上传要求文件来源；下载临时文件须在 delegate 返回前接管；系统终止后用相同 session 标识回接。因此文件所有权和原生任务映射属于账号运行时，不能交给页面生命周期。
- [Apple 文件存储与备份](https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup)：Caches/tmp 可被系统回收。唯一待发送原件必须在持久目录；可重建下载和缩略图放 Caches；备份排除按是否可重建分别确定。
- [Apple Photos picker](https://developer.apple.com/videos/play/wwdc2022/10023/)：大资源优先文件表示加载，提供逐项加载状态。项目继续使用 FileRepresentation 和有界复制，不一次把批量原件读入内存。
- [OSS 预签名上传](https://help.aliyun.com/en/oss/user-guide/upload-files-using-presigned-urls)：临时签名有有效期，过期需重新取得计划。签名不是资源身份，刷新不能删除目录记录；客户端不持有长期 AccessKey。
- [OSS 分片上传](https://help.aliyun.com/en/oss/user-guide/multipart-upload)：真正续传需要 UploadId、分片及完成/中止协议。当前 `V2OSSUploadTransport` 仅声明 httpPut，因此首版明确整文件重传；multipart 列为后续独立工作包，包含分片持久化、校验、重试和遗留碎片回收，不仅添加一个 UI 按钮。
- [OSS GetObject](https://help.aliyun.com/en/oss/developer-reference/getobject)：核验 Range/Content-Range 与 If-Match，版本不匹配重新取得计划；整文件响应不追加到旧 partial。下载结果继续按业务可信长度及 SHA-256 验证。

上述页面支持平台和协议边界；目录布局、并发额度、缓存初值、工作包顺序与性能目标属于结合本项目的工程决定，需实测调整。
