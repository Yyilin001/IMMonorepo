# 本地文本 IM 双账号手测

这份清单用于验证“文本 IM 可内测闭环 v1”。本阶段只覆盖文本消息，不覆盖图片、文件、APNs 或 TestFlight。

## 1. 启动服务端

```sh
cd IMServer
swift run
```

默认地址：

- HTTP: `http://127.0.0.1:8080`
- TCP: `127.0.0.1:9000`

## 2. 启动客户端

```sh
xcodebuild \
  -project IMApp/IMApp.xcodeproj \
  -scheme IMApp \
  -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  build-for-testing
```

手测时建议用两个模拟器，分别登录账号 A 和账号 B。

## 3. 账号与通讯录

1. 注册或登录账号 A。
2. 注册或登录账号 B。
3. A 在通讯录里向 B 发送好友申请。
4. B 在“新的朋友/申请”里接受。
5. A 和 B 的通讯录都应出现对方。
6. 从通讯录点击好友发起私聊，应进入 direct 会话。

验收结果：

- 好友申请接受前，不应直接出现在联系人列表。
- 接受后，双方都能看到联系人。
- 从联系人发起私聊时，重复点击应打开同一个 direct 会话，不生成重复 direct。

## 4. 私聊文本

1. A 从通讯录打开 B 的私聊。
2. A 发送一条文本。
3. B 应通过 TCP 实时收到。
4. B 回复一条文本。
5. A 应实时收到。
6. 退出详情页再进入，历史消息应仍然存在。

验收结果：

- 会话列表 preview、详情消息、历史拉取保持一致。
- 自己发送的消息最终从“发送中”变为“已送达”。
- 对方消息不会重复出现。

## 5. 陌生人 direct 限制

1. 准备两个不是好友的账号 C 和 D。
2. C 创建 D 的私聊 direct。
3. C 发送第一条文本，应成功。
4. C 继续发送第二条文本，应失败并显示“你们还不是好友，对方回复前只能发送一条消息。”
5. D 回复一条文本。
6. C 再发送文本，应成功。

验收结果：

- 限制只作用于 `direct` 会话。
- 第二条被拒后不会自动重试。
- 失败消息保留在 UI 中，并显示明确失败原因。

## 6. 两人群聊不受陌生人限制

1. 用不是好友的账号 C 和 D。
2. C 新建会话时选择“群聊”，只填写 D 一个邮箱。
3. C 连续发送两条文本。

验收结果：

- 会话类型显示为“群聊”。
- 即使只有 2 名成员，也不触发陌生人 direct 一条消息限制。
- 重复创建 2 人群聊可以生成不同 group 会话。

## 7. 断线、待发送队列与手动重试

1. A 打开任意会话。
2. 停止 IMServer 或断开网络。
3. A 连续发送 3 条文本，应出现“待发送”状态。
4. 重新启动 IMServer，等待客户端 TCP 重连。
5. 观察这 3 条消息自动进入“发送中”并最终送达。
6. 对网络失败或“未确认”的消息，可点击消息上的“重试/立即发送”入口。

验收结果：

- TCP 未连接时，新消息先进入本地待发送队列，而不是直接失败。
- TCP 重连后，待发送消息按创建顺序自动发送。
- 手动重试复用原 `clientMessageID`，服务端 ack 或补洞后不会重复展示。
- 业务拒绝类失败，例如陌生人限制，不显示可用重试路径。
- 如果同一条消息因为重试被服务端收到多次，服务端只落库第一条，后续返回同一个 `messageID/serverSequence`。

## 8. 重启恢复

1. A 和 B 完成几轮文本收发。
2. 杀掉 A 的 App。
3. 重新启动并恢复登录。
4. 进入消息 Tab 和最近会话。

验收结果：

- 冷启动先显示本地缓存的会话和最近消息。
- 重启前处于“待发送”的消息，恢复登录和 TCP 建连后会自动发送。
- 重启前仍处于“发送中”的本地消息，恢复后显示为“未确认，可重试”，不会自动重发。
- TCP 建连后只对已加载且落后的会话执行补洞。
- 补洞后没有重复消息，未读和 preview 不回退。
