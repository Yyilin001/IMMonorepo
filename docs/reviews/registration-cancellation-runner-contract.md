# 遗弃注册自动取消与冷启动归属

对应 B08。本批把请求前证明接入实际恢复编排，不关闭旧版本会话清理或真实系统中断验收。PostgreSQL 29、protocol 27、SQLite 173/5 不变。

## 持久状态

注册 ledger 使用 format 3：pending 为尚未完成的注册租约，abandoned 为包含完整证明、UInt32 尝试数、下次执行时间和暂停原因的任务，legacy 继续保存无法补造证明的旧 ID。三类总数仍最多 256；Keychain account 和设备本地保护等级不变。

format 2 的证明迁移为初始任务，保留 pending 与 legacy；format 1 直接迁移为 legacy 档案。迁移写入失败保留原字节。相同证明重复交接不重置已保存的尝试数、退避或暂停状态。网络执行器的完成和失败提交比较完整任务快照，迟到旧结果不能覆盖手动重试后的状态。

## 冷启动

App 在开放交互登录前读取持久凭据，先协调请求前记录，再协调已收到结果的恢复记录。pending 的设备 ID 匹配当前持久凭据且凭据没有待撤销标记时，只退休本地 pending。服务器设备会话 ID 唯一，注册存储不会重用该 ID，因此这是未完成本地 finalizer 的已接管登录。

其余 pending 原子进入 abandoned；空凭据、其他设备和待撤销凭据都不能接管原 pending。该方法只用于冷启动，不能对当前进程正在进行的交互签发运行。已经 abandoned 的任务不会因仍存在旧凭据而撤销取消意图。Keychain 暂不可读取时，App 停留在等待解锁状态，不把未知凭据当作不存在。

## 执行与反馈

- 单一 App 生命周期 owner，不读取账号令牌，不刷新登录。每次最多处理四项，单项网络错误不阻塞其他设备。
- 网络、408、5xx 使用 2 秒起始指数退避，上限 300 秒；429 的 Retry-After 合并退避，最多 86400 秒。错误响应/无效请求进入持久暂停，显式重试只恢复暂停项，不改变普通退避项。
- 本地签发期限过期不等于会话已经结束。只有取消接口确认的 204 或 410 结果才完成任务；410 表示服务端确认期限结束，不宣称执行了撤销事务。
- 使用先订阅后查询的调度器，空队列不轮询 Keychain。任务或迁移保存成功才发出状态通知。
- App 前台运行，进入后台取消并保留 task handle，等实际在途请求结束后才能启动下一次 run；迟到结果在 Task 取消后不修改任务。
- 登录界面和已登录界面均使用现有清理反馈。两类队列聚合优先级为无法读取、暂停、待处理、空；显式重试同时处理两队列并重新订阅状态。

## 证据与边界

见 [本批证据](evidence/20260907-registration-cancellation-runner/manifest.json)。客户端覆盖响应丢失/重建、服务端期限、有限批次与失败隔离、自动发现与重试、取消期间单飞、持久完成失败、旧格式迁移、冷启动归属、暂停恢复及旧快照提交。签名 App 测试使用真实 Keychain，验证已接管与未接管证明的冷启动处理，以及暂停取消任务的反馈和手动恢复。

真实 HTTPS 用例先在 transport 层丢弃整个签发响应，再重建 owner 并执行冷恢复；随后丢失第一次已提交的取消响应，使用执行器记录退避并再次请求同一证明。此用例使用内存持久适配器重建 owner，结合独立真实 Keychain 测试；不是物理断网、进程强杀或锁屏设备证据。

仍需完成 legacy 档案/旧服务端会话清理与部署切换、真实系统中断验收、长期取消记录保留/GC。自动恢复仅在 App 获得执行时间时运行，不能保证退出 App 后立即到达服务端。
