# B05 密码输入、Argon2id 与旧凭据边界

密码入口保留 12–1024 UTF-8 字节，拒绝 NUL；不 trim、截断或做 Unicode 归一化。JSON 到 Swift 再到 C 哈希的密码参数使用显式 UTF-8 字节数，73 字节后的后缀参与计算。客户端无需改协议。

## 实现与持久编码

采用 [Argon2 官方参考实现](https://github.com/P-H-C/phc-winner-argon2/tree/62358ba2123abd17fccf2a108a301d4b52c01a7c) 的 20190702 固定提交，保留原始源码和双许可，逐文件哈希见 `IMV2Server/Sources/CIMV2Argon2/UPSTREAM.json`。编译可移植 reference C 和 `ARGON2_NO_THREADS`，不依赖主机上另装库，也不自行改写密码算法。

当前策略为 Argon2id v19、64 MiB、t=3、p=1，随机 16 字节盐、32 字节输出。参数属于本应用策略；不能将 p=1 描述为 RFC 9106 的完整推荐组合。官方算法说明和向量见 [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)。

数据库保存标准 PHC 字符串，其算法、v=19 和完整参数均显式编码，长度符合既有 60–255 字符约束。算法版本不充当账号或会话代次；并发凭据确认比较完整原 PHC 值（含随机盐），而非只比较 v=19。没有后台重哈希或覆盖并发改密的路径，本批不增 schema。

验证前严格限制编码长度、算法、版本、参数、盐和输出的规范 Base64；数据库中的恶意 m/t/p 不能触发额外内存/CPU 分配。不支持的格式和 legacy bcrypt 都用当前固定策略的公开 non-account dummy verifier 执行同成本拒绝；不能把 dummy 比较成功当作已有账号。

## 并发、取消与生命周期

每个 Account application 拥有一个独立双线程池，最多两次 KDF，算法工作内存上限为 128 MiB，另需预留 Swift/Vapor、数据库和栈等开销。入口依旧执行 edge 和持久账号风险限流，HTTP body 默认上限 16 KiB，随后校验输入，最后进入 KDF。

本版等待队列容量为零，等待期限也为零：两个执行位占满时立即返回 no-store 503 / Retry-After: 1，不持有更多明文排队。KDF 前后不持 DB 连接或事务。取消尚未开始的工作可撤销排队提交；已进入 C 的工作不可抢占，直到返回才归还执行位。停机先停止准入，再排空并关闭工作池；并发 shutdown 调用共享同一排空任务。

## 登录与并发凭据替换

登录先读凭据，再在独立池验证，最后在 PostgreSQL 事务中按 handle 取失败窗口 advisory lock、锁定凭据行并比较最初读取的 user/完整 PHC 值。只有仍相符且账号未被禁用，才清理失败窗口并写成功审计。凭据在计算期间被替换时不产生成功审计或账户断言，也不覆盖新 hash。

这一事务的行锁与真实改密 UPDATE 互斥；它不是通用账号撤销或已签发断言吊销机制，后续凭据签发/禁用仍遵循现有账号规则。

## 旧账号与部署

旧 bcrypt 无法证明用户最初设置的 72 字节后缀或 NUL 后内容。旧记录保留原样，但密码入口拒绝其断言，也不静默升级为 Argon2id；不能凭一个等价前缀创建新的完整输入身份。未知账号、旧账号和不支持的记录均进行固定成本 KDF。

当前绿地环境应使用新算法注册测试账号。若存在必须保留的旧账号，需独立可信设备/Passkey 或批准的恢复流程确认身份后重新设密；本批没有增加仅凭旧密码的恢复入口，也未对用户数据库执行重置或清理。生产旧账号的受限提示/恢复流程仍需验收。

`IM_V2_PASSWORD_DUMMY_BCRYPT_HASH` 已退出当前配置，固定同成本 dummy 与算法策略一起发布。已有本地环境只需移除该废弃键，保留其他密钥；无需重建 PostgreSQL 或更换现有 secrets。新的本地环境不再依赖 htpasswd。生产内存预算和并发容量还需在最终 Linux binary 与完整 workload 下校准。

## 证据范围

修复前真实 HTTP 反例为 2 项测试 / 6 个参数场景 / 9 issues，覆盖 71/72/73/1024 字节和两入口 NUL。新增验证包含官方 Argon2id 向量、完整 UTF-8/空白/规范化差异、随机盐、畸形或超资源参数、同成本拒绝、饱和 503、取消后的执行位占用、停机排空、真实 PostgreSQL 注册/登录/审计及计算期间凭据替换。

最终 **39 项测试 / 7 套件**通过、退出 0。32 请求实际突发为 2 执行 / 30 busy，含后续恢复哈希/验证的本地 Debug 总时间 1.596 秒；这不是生产吞吐数字。首轮 18 项通过后，扩展测试发现固定 dummy 盐误为 17 字节；修正为 16 字节后最终全部通过，失败日志保留。成功审计故障注入证明失败窗口清理与审计原子回滚。
