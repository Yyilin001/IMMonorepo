# Room Virtual Actor writer ledger

Audited against clean business commit `f1cdd78d6a21bf0ae23da627c0710c65115236aa`. This is an **entry and table inventory**, not evidence that an Actor or activation fence currently exists. `owner route` below means the existing `room_owner_routes`/ownerEpoch check; R1 must add activation token validation in the **same transaction**, with room lock held until commit. A table containing `room_id` is not automatically room authority; the last section records control/projection exceptions. All rows need integration and fault evidence before G4.

## External writes and why they remain external

| Existing entry and table | Boundary / required invalidation |
| --- | --- |
| `PostgresV2DirectMessagingStore.setStrangerMessagePermission/setUserAddPermission` → `user_stranger_message_preferences`, `user_add_preferences`, preference operation rows, `user_direct_send_policy_versions`, sync/outbox | User/control policy. Send must read current version/control grant; warmed Actor cannot grandfather a sender. |
| `PostgresV2ReadReceiptStore.setPreferences`, `V2ReadReceiptPreferencePropagationWorker` → `user_read_receipt_preferences`, preference operations/outbox and user sync/projection | User privacy. Reader query must recheck visibility; preference propagation does not grant room write qualification. |
| `PostgresV2ProfilePresentationStore.updateContactAlias` → `user_contact_aliases` and operation rows | User-owned display projection. Same source file as room nickname needs C0 extraction; only nickname goes through room. |
| `PostgresV2MediaStore`/upload/download/session, scan/retention/purge workers → `media_objects`, grants/operations and scan/purge outboxes | Device/media authority and bytes remain media domain; message reference acceptance and message-locator visibility require room capability. |
| `V2ConversationCapabilitiesService` → user room preference/favorite operation rows; `PostgresV2SyncStore`, snapshot/reset, user projection/outbox workers | User-owned conversation/sync state. Room visibility prerequisites must be explicit; no room fact is restored from these projections. |
| `V2DirectRoomProfilePropagationWorker`, `V2ReadReceiptPreferencePropagationWorker` → profile/preference outbox and user sync rows | User projection checkpoint, not room authority. Multi-owner enumeration and revision invalidation must be retained. |
| Account disable/social/block/policy stores; push/wake/typing/presence brokers and `group_event_wake_outbox` | Control authority or ephemeral hints. Every room command checks current policy/version; hints cannot confirm or recover a room command. |
| `V2ControlPlaneHousekeepingWorker` control categories `media_scan_outbox`, `media_purge_outbox`, `public_profile_update_outbox`, `read_receipt_preference_propagation_outbox`, `push_wake_outbox`, `device_credential_operations`, `device_refresh_token_history`, `user_live_presence_leases`, user preference/relationship/session operation rows | These do not alter room authority. Its `roomOwned: true` classes **do**: `direct_room_operations`, `room_membership_operations`, `message_withdrawal_operations`, `moderation_operations`, `message_edit_operations`, `read_receipt_operations`, `message_reaction_operations`, `group_room_operations`, `room_pinned_message_operations`, `group_announcement_operations`, `group_permission_operations`, `group_role_operations`, `special_account_message_operations`, `room_member_nickname_operations`, plus `content_review_jobs`. Creation bootstrap operation cleanup needs a closed coordinator rule if no activation exists. |

`V2GatewayDomainCommandHandler.handleWithoutTelemetry` is the current Gateway switch, `V2VaporProfilePresentationRoutes`, `V2VaporGroupInvitationRoutes`, and `V2VaporMediaEdgeRoutes` are the relevant HTTP entries. ServerApp and AccountApp construct the workers; see [file ownership](file-ownership.md). This ledger lists real writer symbols/tables from source inspection; it does not treat absence of a `V2Routed*` name as a coverage test.
