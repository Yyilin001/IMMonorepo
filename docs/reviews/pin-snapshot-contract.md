# B06 置顶快照顺序与取消状态

更新：2026-09-06。服务端置顶投影使用独立的类型边界和源房间版本比较；后续[客户端 reducer 与受控迁移](pin-effect-contract.md)已实现，旧历史权威恢复与发布切换仍未完成，B06 继续实施中。

## 当前行为

`V2PinnedMessageSnapshotEffect` 校验事件类型、room/message/可选 actor UUID、布尔置顶值、非负毫秒时间及可选正 Int64 源 room sequence。个人同步游标只决定投影版本的有效区间，不决定置顶事实的新旧；墙上时钟也不用于排序。

`PostgresV2UserProjectionWorker` 对每条置顶事实先读取同一用户、房间、消息的当前投影，比较源序号。已知旧版本不能覆盖新版本；相同源版本不同来源拒绝；同一来源改变内容或已知源序号同样拒绝。重复当前事实不增加投影版本。失败沿用工作器事务回滚和持久重试/暂停机制，不推进失败用户的 checkpoint。

取消置顶是当前的负事实，保存 `is_pinned=false`、源事件身份和源版本；不会调用删除投影。新构建的快照因此携带取消状态，可阻止支持该排序合同的消费者用旧置顶覆盖它。现存 UUID 大小写组合通过有限的键候选读取，延续已有物理键，避免为一个对象建立第二条当前投影。若候选中已有重复当前对象，拒绝而不是任选一条。

## 旧数据边界

旧正文缺少 `room_sequence` 时仍接受，值保持未知，不用个人游标或时间回填。相同来源的后续观察可补充缺失序号；不能降级已知序号。已知版本状态不被缺序号的旧观察覆盖，带版本的新观察可以替换未知旧观察。

两条都缺序号、且来源不同的历史事实仍保留兼容的到达顺序处理；本批没有证明其真实发生顺序。这个缺口必须由后续受控源历史/权威基线恢复解决。旧 worker 已经删除的取消置顶记录也不会凭空重建。当前比较规则要求升级源 writer 后不再混用缺字段的 writer；所有投影 worker 也须一致切换，否则旧 worker 仍可删除负事实。尚未执行生产切换或历史迁移。

工作器的额外身份校验依赖当前对象；数据库现有的不可变 projection effect 约束会在日志写入阶段拒绝已保留来源的内容变更。本批没有新增独立置顶 receipts 或改变既有保留期；更早历史及清理后的来源保护仍需统一保留/GC 合同覆盖。成员退出后旧事实是否可恢复房间范围、撤回消息的置顶语义和客户端四条消费路径也仍需组合验收。

## 客户端快照身份校验

ClientKit 的 group capability 快照键与正文改为比较 UUID 身份。仅规范化 room/message/target UUID 段；前缀、角色和其他内容保持精确比较。不同对象、错误角色、缺段、多余段或未知前缀仍被拒绝。原始快照键、正文与摘要不改写，非群管理快照校验保持原合同。该兼容修复不改变客户端置顶 reducer 的排序和旧库迁移状态。
