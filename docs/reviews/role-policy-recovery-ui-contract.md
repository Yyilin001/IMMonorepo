# B06 权限恢复状态与显式重试

更新：2026-09-06。App 已提供暂停提示和“请求同步权限”入口，继续使用已有持久请求及自动执行器。

## 一次读取形成可见状态

ClientKit 新增 `V2ClientGroupRolePolicyState`，在同一次 SQLite read snapshot 中组合角色策略与恢复状态：不可读取、等待个人同步、需要基线、已排队、已暂停、已就绪。请求的账号/安装/成员/代次栅栏过期时显示需要恢复；无账户或无房间授权时返回不可读取且不暴露策略。

已观察到的权限在排队、延后或暂停期间保留；显式空集合不变成默认授权。reset 期间可保留可见值，但状态明确为等待同步。恢复请求现在是用户可见状态，其变更仅通知 conversationDetails，采用普通合并刷新，不触发会话列表或全量紧急刷新。

## App 能力与交互

`V2GroupRolePolicyAccessing` 提供原子状态读取与显式重试，两项均由实际 GRDB datasource 实现，没有默认成功实现。重试调用已有 `resumeRolePolicyBaseline` 创建新请求身份，再读取最新状态；网络工作仍由连接拥有的 runner 执行。

权限弹层分别显示暂停、已保存等待连接、等待会话同步和当前不可读取。需要基线或暂停时提供“请求同步权限”；提交期间禁用该按钮，避免重复创建请求。失败时保留原状态并允许再次尝试，提示“暂时无法确认同步状态”，不把状态读取失败误报成持久请求一定未保存。

不可读取或等待 reset 时禁用编辑/保存；角色不再存在或本地授权撤销时清除原编辑上下文。重试本身保留可见权限和编辑草稿，草稿继续使用开始编辑时的 expectedRevision；重新载入已知策略与重新请求服务器是不同操作。

Store 使用独立读取 generation，避免较早读取或旧失败覆盖新状态；失败反馈在恢复阶段改变后清除。能力未配置时显示不可用，不提供点击后无效的重试。

## 验证与边界

最终 ClientKit **329 项 / 53 套件**、App **176 项 / 17 套件**通过。新增验证覆盖状态转换、延后/暂停跨重启、旧成员栅栏、reset/授权撤销、通知范围、重复点击、失败后再试、不可恢复阶段拒绝提交和能力缺失；交错测试验证旧重试失败不能覆盖新状态，恢复阶段变化会清除过期失败反馈。此前读取交错测试已适配原子状态接口。

按钮采用标准 SwiftUI Form/Button，提供状态值、操作提示和稳定标识 `v2.group.permissions.retry-recovery`；状态区标识为 `v2.group.permissions.recovery`。文案使用 SwiftUI 可本地化文字，不用颜色单独表示状态，也未增加固定高度或单行限制。
