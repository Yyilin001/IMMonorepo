# 实际 App 的旧注册档案跨进程恢复

日期：2026-09-07，对应 B08；继续实施中。

本批把[客户端旧档案恢复](legacy-registration-client-recovery-contract.md)推进到实际 App 进程。测试先通过真实密码注册和设备签发取得旧会话，再将该会话真实的设备 ID 与原签发操作 ID 作为 format 1 档案种入 App 自己的隔离 Keychain。没有旧密码、账号证明或 access/refresh 写入档案。该测试不是运行旧二进制完成升级，起点是明确构造的旧格式数据。

种子入口只编译到 DEBUG，只有 opt-in 本地账号测试模式与 UUID 隔离域才能调用，账号还须满足专用 fixture 前缀。使用 `SecItemAdd`，已有档案不能被覆盖；生产服务名由隔离域派生，不接收任意目标路径或服务名。独立清理入口也限制在该测试域，可移除失败场景留下的 legacy 档案。Release 不包含此种子实现。

App 第一次真实登录在取得新设备绑定的账号证明后提交旧注册清理。专用 HTTPS 代理让账号服务完成事务，保留所有响应字节，等待 XCTest 准备好观察后执行 `simctl terminate`。UI 测试必须观察实际 App 已不运行才继续。第二次启动不带种子参数，必须从第一进程的 Keychain 恢复原档案；重新输入账号密码取得新证明，用原旧设备/操作重放清理，再签发新设备。

代理只针对本次专用账号的旧设备执行一次终止，重放核对原操作不变、新证明绑定设备不同。首次进程未签发的新设备尝试由普通注册取消队列保留并清理。成功登录后再正常终止和冷恢复一次，确认新会话没有被旧清理误删。旧设备访问令牌通过真实 HTTPS 验证已失效。

数据库独立检查该账号只有旧、新两个已签发设备；旧设备已撤销，只有一条 legacy 取消记录和一条撤销事件，无有效旧 access/refresh；首次中断的准备设备从未签发，且其未绑定取消证明已持久取消。结果合同为 `2|1|1|1|0|0|0|1`。

该证据覆盖清理提交后、HTTP 确认前的受控进程终止和真实 Keychain 重放。它不证明任意指令处 SIGKILL、OS jetsam、物理掉电、真机锁屏或所有退出/换号检查点；永久冲突处理与记录保留/GC 仍开放，B08 不关闭。完整运行、失败过程（若有）与当前源码哈希见[证据清单](evidence/20260907-legacy-app-process/manifest.json)。
