# 凭据签发与替换边界

日期：2026-09-07。B08 仍实施中，本批修复三个已复现的副作用缺口。

## 请求前取消

V2HTTPAccountAssertionDeviceCredentialProvider 在设备身份读取、账号因子返回、注册操作读取和注册操作准备完成后检查取消。取消后不会启动下一步因子/持久写入/HTTP。已经进入保存的操作可以完成，保留其 deviceID 与 operationID 供恢复，不在取消路径清除它。

原实现四个挂起点取消后都继续发送签发请求，新增反例产生 14 个失败断言；修复后全通过。另一个反例确认 URLSession 的 URLError.cancelled 被误报为 networkFailure，现保留 CancellationError，同时保留已经写入的重放记录。取消网络等待不证明服务器没有提交。

## 活动旧凭据的替换

旧凭据可能在本地 SQLite 初始化失败后仍然存在，新登录不能直接覆盖它。AuthSession 保存不同 user/device 的新凭据前，先在旧记录保存稳定撤销 ID，再提交独立队列，最后保存新凭据。全过程沿用同一个串行 credential IO，原 pending refresh 字段也保留。已有撤销 ID 被复用；队列失败保留标记与旧凭据，冷启动沿用已有交接恢复。相同设备已标记退出时仍拒绝重新建立。

原实现只处理已有退出标记的旧记录：新反例在无标记情况下确认队列失败仍覆盖旧凭据，且无撤销任务，产生 4 个失败断言。修复后有标记/无标记均保留原操作、阻止失败覆盖并能重试完成。

## 验证

最终 ClientKit 444 报告、439 实际、5 在线跳过（70 套件，5.497 秒）；App 196 报告、195 实际、1 在线跳过（20 套件，5.168 秒）。早期测试表达式编译错误已修正，三组原实现失败日志保留。

真实 HTTPS 与自建 PostgreSQL 5 项/2 套件通过（2.708 秒），持久计数 7|3|0|0|3，兑换 204×4、401×1、409×1；自建数据库和证书目录已清理。该在线运行在最后补充 URLError.cancelled 映射之前；正常签发/刷新/撤销路径未改变，新增错误分支由最终离线回归验证。未新跑 UI/Gateway/headless 或真机系统边界。

## 尚未完成的结果交接

已经发出的请求可能在取消后返回有效凭据。当前 bootstrap 在返回后检查取消/epoch，会拒绝建立旧会话，但不存在跨进程的“已收到、尚未被登录凭据接管”的结果记录。HTTP provider 的 issuedRegistration 是内存值，不能作为持久恢复证据。单纯加一次撤销调用会在队列不可写、进程退出或同一注册重放被另一尝试接管时留下缺口，不能据此关闭问题。

完全丢失响应时，原注册记录只有 deviceID/operationID；当前撤销接口需要尚未收到的能力证明。不能借用新账号凭据清理旧请求，也不能持久保存账号密码来伪造独立恢复。后续需明确注册请求、返回结果、凭据接管与废弃的持久归属，并验证服务器已提交而客户端没有响应的路径。以上是开放设计要求，不是本批实现或验证结论。
