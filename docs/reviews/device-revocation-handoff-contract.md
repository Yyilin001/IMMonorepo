# 退出时撤销能力的持久交接

日期：2026-09-07。范围：B08 的 ClientKit 凭据生命周期与 App 组装。B08 仍实施中；本合同不覆盖联网执行器或完整退出体验。

## 持久顺序

`V2AuthSession` 的终态删除在原有串行 credential IO 所有者内完成四步：读取旧凭据；将稳定的 `pendingRevocationOperationID` 写入同一个凭据记录；把旧 user/device/capability/deadline/operation 写入独立撤销队列；最后删除登录凭据。队列保存成功是删除前置条件，过程不调用网络、不刷新令牌。

- 原凭据标记保存失败：保留凭据，App 更早保存的文件退出标记继续禁止恢复。
- 标记成功、队列失败：保留标记和凭据，冷启动只重试交接，不恢复登录态。
- 队列成功、凭据删除失败：冷启动重复入队同一操作，队列不重复建任务或清除其重试状态。
- 若队列任务已被确认完成，但原凭据删除仍未成功，重启可重新提交同一 operationID。服务端幂等合同处理重放，不生成新撤销身份。
- 旧 IO 已开始时，新登录保存排在其实际副作用之后；旧调用最终得到代次失效，不能删除新记录。
- 新登录替换入口也读取旧持久记录。发现退出标记时先交接，再原子替换；失败保留旧记录，不允许同一 user/device 重新建立已标记退出的会话。

临时不可读取的凭据不会被删除。已损坏或永久失效、无法解码出证明的记录沿用不可恢复删除行为，不宣称这些情况已完成服务端撤销。未开始执行的终态调用仍依赖 App 的持久退出标记及登录 gate；本批不解决注册响应迟到形成的孤立服务端会话。

## 独立队列

一个凭据 service 对应一个 `V2DeviceRevocationStore` owner。队列只保存撤销能力及其旧身份，不保存 access/refresh token，不引用新会话或 `V2AuthSession`。App 生产组装必须注入真实队列；旧签名的便利初始化器只存在于测试 target，并显式使用内存假实现。

Keychain account 为 `device-revocation-outbox-v1`，版本为 1，最多 256 条。保存通过单个 Keychain item 的同步替换完成；损坏、版本错误、容量溢出和同操作/同设备冲突均失败并保留原数据。一个 owner 内没有跨 await 的读改写窗口。

撤销 item 使用 `AfterFirstUnlockThisDeviceOnly`，仅放宽目的受限的撤销权限以支持后续延迟清理。登录凭据继续使用 `WhenUnlockedThisDeviceOnly`。按 service 隔离账号安装/测试命名空间；不跨设备备份同步。

任务持久保存尝试次数、下次时间和暂停原因。失败与完成以完整原任务做 CAS；旧完成不能抹掉较新的重试/暂停状态。重复 enqueue 不重置任务。到达本机 capability deadline 不代表服务端确认，因此 `due` 不按本地过期时间删除任务。

## 验证与限制

断点恢复测试通过新建 AuthSession/队列 owner 并复用持久后端模拟进程内存丢失；它不是在任意指令处杀死真实进程的证明。真实模拟器 Keychain 用受控删除失败验证两个 item、保护等级、重建 owner、原操作重用、换号后的完成隔离和测试作用域清理。模拟器不证明物理设备锁屏时的系统行为。

本批尚未实现独立联网执行器、自动退避驱动、暂停后的用户恢复入口或 App 后台调度。App 显式退出仍先执行旧的 Push 端点网络清理，断网退出仍可能受阻；后续需替换为本地交接与独立撤销执行。不可把当前入队成功表述为服务端已撤销。

协议 27、PostgreSQL 28、SQLite 173/5 和 47 项问题状态统计均保持不变。验证日志和最终源码哈希见 [本批证据](evidence/20260907-revocation-handoff/manifest.json)。
