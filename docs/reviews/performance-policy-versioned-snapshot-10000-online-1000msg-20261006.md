# 版本化权限快照压测：10,000 在线 / 1,000 msg/s

日期：2026-10-06；有效运行 R26。代码已完成权限读取与租约分离、版本化主动推送、移除读取调度额度。

## 结论

权限读取路径的固定冷加载调度队列已经移除。真实 PostgreSQL/TCP 测试证明初始化不认领租约、不锁业务事实，热读取和策略变更后的读取不新增 Owner 获取请求。

本次整体消息吞吐仍未达标：全部 12 个 loader 达到 10,000 在线，约 20 秒后消息重试耗尽触发 guard，未完成目标 60 秒窗口。只有 2/12 客户端返回最终报告；不能据此给出完整系统吞吐、总体延迟分位数或提升百分比。

## 场景与证据

- 六个 Gateway，十二个 loader，10,000 个连接，1,000 新消息/秒，128 字节消息，真实 TCP 提交与回执查询。
- 使用与 R24 相同的 fixture manifest、scenario、edge source 和 configuration defaults；相关证据哈希核对相同。
- 脚本使用 `--allow-scaled-diagnostic`，属于 10,000 连接的缩放诊断。
- 原始结果：`/tmp/imv2-versioned-policy-10k1000-20261006-r26/candidate/`。
- 受限窗口阶段汇总：`/tmp/imv2-snapshot-r26-comparison.json`。
- R25 在连接阶段因测试 PostgreSQL 端口与 loader 源端口范围冲突停止，未进入发送阶段，已排除。测试数据库停止后用相同参数重跑 R26。

正式质量标志 qualityPassed/capacityCompleted/steadyStateCompleted/steadyStateCommonWindowPassed/drained 均为 false，完整公共窗口为 0 秒。

仍需后续定位消息事务、连接竞争、读取压力和停机 drain；本次不扩大权限改造为完整消息持久化重构或真实环境故障闭环。

### 失败与清理
