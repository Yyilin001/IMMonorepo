# 消息变更的接受事实与房间日志

对应 B03、B06 与 D07。当前普通编辑、作者撤回和 reaction 的公共效果进入
有序房间日志；不再由消息接受时选择逐用户扇出或房间日志。

## 权威来源

`message_send_completions` 保存不可变的 message ID、接受事件 ID、房间序号、
发送请求指纹与接受时的成员版本。原消息正文或其当前修订不是接受身份的替代品，
也不能仅凭当前成员身份推断历史内容可见性。

新变更在 owner、房间、消息与操作版本检查后读取并验证原接受事实；
缺失或不匹配的接受记录不得产生新的变更效果。已完成的同一操作重放仍按自己的
幂等结果返回，不重新修改消息。接受记录的保留/清理以
[发送完成记录合同](message-send-contract.md)为准。

## 公共事件与读取

私聊和两类群的普通变更使用同一房间事件顺序与房间游标。
物理接受事件可位于 `messages` 行或 `room_events` 行；这一布局不决定变更投递模式。
原接受消息的历史正文必须按对应内容版本重建，后来的编辑不能倒写进原接受事件。

房间 pull 对调用者当前资格、原消息接受时和具体变更提交时的可见性做检查，
不可见事件可计入已扫描的 continuation，但不能出现在返回内容中。
新编辑提供带接受身份的完整替换状态，客户端可跨越合法版本缺口；
迟到的旧接受事件不得覆盖新投影。详见[读取与游标合同](message-mutation-read-contract.md)
和[完整编辑合同](message-edit-replacement-contract.md)。

审核删文等回溯性内容撤销另按其专门合同处理；不能把普通作者撤回推断为
已从所有历史本地副本、搜索索引和缓存完成追溯擦除。

## 验证

对私聊、标准群和大群分别验证编辑、撤回与 reaction：
缺失/冲突接受事实时事务无副作用，完成后丢响应可按原操作重放，
接受事件和后续变更按房间顺序恢复，离群/重入与乱序版本不泄漏正文或复活终态。
旧逐用户扇出实施和测试数字仅保留在
[历史运行记录](verification-records.md#20260906-message-delivery-authority)中，
不作为当前协议、schema 或容量结论。
