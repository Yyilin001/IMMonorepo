# Reusing durable room publication responsibility

Business transactions already commit the canonical ordered room facts (`room_events`, or compact accepted `messages`) and statement-triggered `realtime_dirty_room_heads`. Both ordinary log inserts and compact message inserts coalesce H and advance dirty revision atomically. Membership/room control triggers UPSERT the current room H and metadata, so even a control-only room at H=0 gets a new dirty revision in the same transaction. This is the retained publishing responsibility; the bounded immutable feed only accelerates consumption. MAX(room_sequence) over the transition table is safe because it aggregates this transaction's committed room order, not a global preallocated identity sequence.

Control journal remains independent: its publisher verifies contiguous per-topic control versions, assigns journal ordinals while holding its source partition lease, and commits append, outbox deletion, version floor and published-through together. It never treats MAX(preallocated source event ID) as a committed prefix. Room Source page consumption verifies a consecutive room sequence and historical membership controls at one MVCC cut, so a dirty H cannot skip unseen controls or apply current authorization to old events.

Production Factory now installs an activation-scoped dirty-head probe and CAS acknowledgment in the existing physical RoomSubscriptionHost checker/worker. Production discovery starts with the pending partial index in (partition_id,room_id) order, joins the actual host/incarnation live lease and current owner, and returns at most 128 changes. Its monotonic cursor advances past returned rows and resets at exhaustion for fairness; Host pins every returned actual token against its active entry before scheduling any read. It no longer enumerates all active tokens for dirty discovery. The old token-list dirty lookup has been removed; fence regression tests use the same host-indexed discovery as production. There is no interest scan per Gateway. Pending rows lacking a live host lease remain durable and cannot block the output cursor with repeated work. The SQL can still traverse other hosts' or inactive pending rows while filtering; dedicated shard ownership/indexed host targeting is a remaining scaling step, not a claimed elimination of all pending discovery work. Inactive pending responsibility remains durable and is picked up when its room is restored/registered. No new poller, outbox, schema or network-held SQL transaction is introduced.

The lease/head probe still independently detects expired/replaced activation every existing check cycle. Dirty absence never grants lease validity. Dirty discovery is required at construction. Only dirty receipts drive recovery or head retention; the former periodic room-H recovery fallback and token-list callback have been removed. Host does not cache a second consumed-through cursor; Owner owns that cursor. Transient dirty-query failure retries on the same owned checker; admission/transaction failures retain the exact pending receipt. Feed overflow/gaps use the existing coalesced Source repair.

Completion is Owner consecutive ingestion through receipt H followed by Owner's ordered local shared-head retention (`refreshHeads`), not a peer/socket ACK. Then DB CAS matches room, dirty revision, H, control version, owner epoch and exact currently live activation. The update only sets pending=false; it never deletes latest H. A later commit changes revision and survives a stale ACK. A lost/unknown ACK is idempotent. Host crash after local retention relies on the canonical room log and a fresh activation/grant snapshot, while Gateway expiry/exact fences and the client H/G/C synchronization close the delivery loop. CAS does not claim every client saw the last frame.

Actor composition does not construct or run the legacy room wake relay; explicit publication migration disables its write triggers after transferring responsibility. Local-only composition still uses that relay. Journal publisher no longer accepts a room head store or ApplyHeads callback, so it cannot become a second dirty-head publication scheduler alongside Host. The unused online-head dispatcher and unused non-room control callback have also been removed.

Validation added for root execution: real PostgreSQL production triggers produce receipts; a later committed H survives stale receipt CAS; inactive room stays pending; wrong exact token is excluded; a 4096-row inactive population yields the pending partial-index query plan with no LockRows. Host test loses its fast notification, repairs once through Source, records durable completion and shows repeated fresh lease checks do not re-read the unchanged log. This agent ran diff whitespace validation only, not builds/services.

## Same-H authorization cuts

The canonical room control version is selected with the same repeatable-read snapshot as membership and H, and carried in each fresh lease proof. The Owner records the version whose permission cut it has processed. Renewal requires both exact H and exact processed control version; identical H alone is insufficient. The physical proof broker preserves this version when subtracting elapsed time.

A pending dirty receipt is reconciled before ordinary room draining. If continuous room-log controls produce exactly the fresh membership cut, no reset is required. If history cannot establish that cut, the Owner drops the skipped historical audience, adopts the complete fresh cut, and retains one ordered `authorizationInvalidated` terminal control on each old shared fence. No ordinary body/head is appended after that terminal. Gateway application clears Ready, grants and queued permits, and returns the exact cumulative receipt. Dirty CAS completion waits for that actual receipt; offer, network start and mere H refresh do not count. If a terminal cannot be delivered, the dirty receipt remains pending; there is no optimistic expiry completion in this implementation.

A host crash before completion leaves the canonical dirty row pending. A replacement activation restores membership/H/control version from a fresh complete snapshot and never carries old shared fences or permits across activation. If the dirty row was completed before a crash, the same fresh-restore rule reconstructs the durable authorization cut from the original room/membership tables; dirty ACK does not delete business history. Early database retirement still does not imply instantaneous Gateway revocation: terminal application or the previously installed conservative lease deadline remains the external authorization boundary.

The PostgreSQL regression uses actual canonical triggers, Source snapshots, Host scheduling, Owner/Relay, pump cumulative receipts and Gateway ingress/authority. It changes membership without adding a room-log sequence, holds the terminal before actual ingress application, proves the dirty receipt is still pending while the old permit is live, then proves terminal application invalidates that permit before CAS clears the responsibility. The Gateway-owned socket regression covers actual writer submission.

## Explicit legacy publication exit

`install_v2_realtime_journal.sh --room-publication actor|local-only` installs the repeatable canonical extension, then executes `realtime-room-publication-mode.sql` in its own database transaction. `--print-sql` emits SQL for an existing Compose/psql boundary without credentials. Direct psql callers pass `-v room_publication_mode=actor` (or `local-only`). Omitting the mode only installs the canonical extension and does not change publication capability. The three local/shard/seed entrypoints derive the explicit mode from resolved Compose Gateway transport, including the authoritative persisted environment, rather than an unrelated terminal export.

The database capability is the actual state of both legacy room wake triggers, not a new runtime flag or a mode marker table. Runtime readiness requires both disabled in Actor mode, both enabled in localOnly mode, and rejects a mixed state or a mismatch with configured runtime mode. Installation is an explicit deployment transition; quiesce processes before switching a retained database between modes. Runtime performs no DDL.

On the first enabled-to-disabled transition, the migration serializes with extension installation, settles existing room/membership/append/legacy-claim writes under ordered relation locks, and transfers every retained business room cut to canonical pending dirty rows. Legacy target H ahead of the durable business H is rejected. UPSERT retains maximum H, owner epoch and control version, increments revision and sets pending, so an older exact receipt cannot erase the transferred cut or a newer concurrent cut. Only after transfer does it disable both legacy write triggers and delete duplicate legacy wake hints; business room events, messages and membership history remain intact. No RPC runs under these locks. Transaction-local lock timeout is 5 seconds and statement timeout is 30 seconds; failure rolls the whole transfer back. The durable consumer still owns actual processing/receipt completion independently.

Both triggers already disabled means transition completed: repeated Actor installation does not scan/backfill all rooms, advance revisions, or re-dirty completed responsibilities. Explicit localOnly installation enables both legacy triggers and retains the local relay path. Canonical control capture remains mandatory; this mode migration does not address physical shard consumer ownership, which is a separate later stage.
