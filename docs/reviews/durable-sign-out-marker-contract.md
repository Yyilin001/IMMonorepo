# B08：可报错的退出意图记录

B08 保持实施中。本批把退出流程中的非敏感意图改为文件记录，并调整本地完成顺序。远端设备撤销、旧 session 专用离线补偿 capability、完整清理 checkpoint、账号切换及逐步骤强杀恢复仍未完成。

## 记录合同

旧实现用 UserDefaults Bool，三个协议方法均不抛错。应用无法区分退出意图已提交与存储未能保存，不能据此证明写入退出意图后才删除凭据。本批未声称已复现某次 UserDefaults 丢写或设备断电。

现在 `V2FilePendingCredentialDeletionStore` 只保存版本和 pending 值，不包含 token 或账号标识。文件名由既有数据库路径和 Keychain service 派生标识的 SHA-256 决定；不同 DEBUG 测试域或不同 service 不共用记录。每次写入执行原子替换、应用本地文件保护/排除备份策略，并请求文件同步；失败向调用方传播。

只把明确的文件不存在视为没有退出意图。读取失败、JSON 损坏或未知版本均报错，App 停留在退出待完成状态，不能继续恢复凭据。项目未上线，不读取也不迁移旧 UserDefaults 标记。

完成时写入 `pending=false`，保留这个明确完成记录。此处没有把记录扩充为已完成的多阶段退出状态机。

## App 顺序

1. 显式退出先提交 pending 记录，成功后才使旧认证工作失效、处理 Push 移除及删除凭据。提交失败时不继续删除凭据，并保留本进程的退出待完成页面以重试。
2. 凭据删除成功后，停止账号任务并关闭捕获的本地 store。关闭失败时保持记录，不能提前宣称完成。
3. 只有关闭成功才写完成记录并展示登录页。完成记录写入失败仍保持待完成页面。
4. 手动重试和 scene 激活共用退出单飞 gate；在文件读写等待前占用 launching 路由，避免等待完成记录时又发起重试。
5. 冷启动先检查记录；即使凭据已被先前的认证终止删除，也继续本地完成流程，不要求重新建立认证会话。

文件本身不能保证磁盘完全不可写时仍记住用户意图；这种情况下接口报错，且显式退出不进入凭据删除步骤。本批也未证明整机断电持久性、目录 fsync 或每一个 await 的进程强杀恢复。

## 验证边界

测试覆盖跨实例 pending/完成读取、旧标记迁移、无法读取或写入时的错误传播及旧标记保留、损坏/未知版本拒绝、同数据库不同 Keychain service 文件隔离，以及完成记录对残留旧偏好的优先级。

模拟器可验证排除备份属性，但不返回文件保护属性。两次初始测试已记录这一限制；最终保留真机上的 Complete 属性断言，模拟器不把它计作已验证。锁屏 Keychain/FileProtection 验收仍开放。

具体运行、失败记录、日志和源文件哈希见 [manifest](../../docs/reviews/verification-records.md#20260906-durable-sign-out-marker)。现有真实认证终止 UI 验收只验证本次改动没有破坏登录恢复、远端撤销后的退出及冷启动，不等同于显式退出全部步骤的崩溃恢复验收。
