# 旧注册档案的服务端取消仲裁

> 2026-09-20 当前范围：项目未上线，不保留历史兼容。旧设备注册取消服务及专用表已删除；当前注册取消、设备撤销及其并发保护保留。 以下内容仅保留为历史记录。

日期：2026-09-07。对应 B08，仍实施中。本批提供服务端事务能力；旧档案的 HTTP、ClientKit 和 App 清理接线尚未完成。

旧版注册档案只有设备 ID 和操作 ID，没有请求前生成的取消证明。设备不存在时执行普通撤销并返回 404，无法阻止先前的注册请求稍后签发。旧 ID 也不能独立构成撤销权限。

新增可信域请求要求上层重新验证账号因子，并将验证绑定到本次新设备 ID；服务端只允许清理该已验证账号下的旧设备，新旧设备 ID 必须不同。当前没有公开 HTTP 入口，域构造器的类型校验不能代替账号因子验证。后续接线必须在验证成功后构造请求，不能接受调用方自报 user ID。

取消按账号锁、注册设备锁、设备行锁的顺序串行化，与签发共用账号及注册锁。账号禁用或特殊账号不可执行；设备已属于其他账号时拒绝。首次取消持久保存账号、设备、原操作 ID 和时间；设备已签发时，同一事务撤销设备、访问/刷新凭据及 Push 资格，写入一次撤销事件。事务失败不能留下已取消标记却保留活动会话。

签发在注册锁内查询取消记录，原入口和带证明入口均受约束。同账号的目标设备一旦取消，后续任何操作 ID 都不能重新签发该设备。不存在的设备不会被伪造为会话，也不会被一个账号预占而阻止其他账号使用。其他账号后来使用相同设备 ID 时，原账号重试会得到目标不可用，不能误撤销新所有者。

相同账号、设备和操作重放幂等；设备或操作的矛盾绑定返回冲突。每账号最多 256 条记录，账号锁保证并发请求不能越过上限，达到上限仍可重放已有完整绑定。当前不删除记录；其保留、账号销毁和回收合同继续列入 B15/D04，不能按本地旧请求时间随意删除阻断记录。

PostgreSQL 新环境合同为 `im-v2-current-30`。29→30 迁移只增加空表并更新版本，保留已有凭据，不推断历史取消。启动检查和 SQL 门禁验证列类型、非空、账号内两组唯一约束、有限时间及有效索引。迁移与启用清理前必须停止全部旧签发进程；旧二进制不会读取新阻断表，混跑无法提供此保证。本批没有执行生产迁移或部署。

本批验证结果与失败过程记录在[证据清单](../verification-records.md#20260907-legacy-registration-arbitration)。原生 HTTPS 回归只验证当前签发、刷新和撤销链路兼容 schema 30，不代表旧档案的端到端清理已经可用。

实际验证：26 项 PostgreSQL 集成（32.416 秒）、14 项接口单元（0.011 秒）、5 项原生 HTTPS（2.729 秒）通过。迁移保留旧凭据且新表为空，缺唯一约束及放宽时间约束均被门禁拒绝。首次集成运行因新增测试遗漏 schema 清理产生 12 个问题，修正隔离后全组通过；首次测试编译的类型/参数标签错误也保留日志。没有新跑 App UI、Gateway、headless 或真机验收。
