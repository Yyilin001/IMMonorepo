# 旧注册清理的账号验证与 HTTP 接线

> 2026-09-20 当前范围：项目未上线，不保留历史兼容。旧设备注册取消 HTTP 入口已删除；本文中的旧入口不再可用。当前注册取消接口继续保留。 以下内容仅保留为历史记录。

日期：2026-09-07。B08 继续实施中。本批接通[服务端仲裁](legacy-registration-arbitration-contract.md)的真实账号入口；ClientKit 与 App 尚未消费此接口。

`POST /v2/device-credentials/cancel-legacy-registration` 接受严格四字段 JSON：`accountAssertion`、字符串 UUID `assertionDeviceID`、字符串 UUID `targetDeviceID`、UUID `operationID`。最大请求体 8 KiB，证明最多 4096 UTF-8 字节。缺字段、额外字段、自报 user ID、无效 UUID、空证明及新旧设备相同均在账号验证前拒绝。

Account 生产入口将该路径加入既有持久地址限流，仍经过 trusted-edge 校验；它不依赖当前登录会话。短期账号证明必须由实际账号因子签发并绑定本次新设备，验证成功后才从证明取得 user ID 并调用可信取消事务。调用方的普通 Bearer、旧设备 ID 和操作 ID 都不提供授权。当前 HMAC 证明默认 90 秒，过期、签名无效和绑定不符返回 401；验证基础设施异常返回 503，不误报为账号终止。

取消成功或完整操作重放返回空 204。已禁用/特殊账号返回 403，目标已属于另一账号返回 404，设备或操作矛盾绑定返回 409，每账号 256 条持久记录满额返回 507；地址限流仍为带 Retry-After 的 429。路由自身响应不含目标信息或凭据，使用 no-store/no-cache。**只有 204 确认清理完成**；404 不能清除本地旧档案，507 也不能按短期网络故障无限自动重试。

新设备绑定的同一份账号因子结果可先提交旧档案清理，再签发新设备凭据，不需要在客户端为这两步重复保存密码。网络失败或本地确认写入失败仍应保留完整旧档案，之后重新验证账号再重放原操作。App 所需完整档案 CAS、登录用例接线及失败反馈留待后续完成，不应把本批 HTTP 可用等同于旧档案自动恢复已完成。

测试使用真实 HMAC 校验验证过期、伪造、普通访问令牌及设备绑定错误；模拟服务验证所有状态与严格字段，可信边缘/地址门禁验证在账号因子调用前生效。真实原生账号服务与 HTTPS 扩展通过密码注册/验证取得证明，完成故障回滚、幂等撤销、同一证明的新设备登录、未签发取消、另一账号设备隔离和容量边界。扩展在既有基线数据库统计之后运行，另建三个设备、一条撤销事件及 256 条账号范围取消记录；其中 254 条仅为配额测试直接种入。

首轮 HTTPS 扩展误把已取消设备再次签发的既有 403 合同写成 401。服务端已正确拒绝，修正测试预期后全链路通过；失败记录保留。没有生产迁移或部署，schema 30/protocol 27/SQLite 173/5 不变；仍需在启用清理前停止旧签发二进制。
