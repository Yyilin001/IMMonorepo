# 账号生命周期内的 HTTP 认证处理

后续状态更新：B09 已完成[真实 App 与 TLS Gateway 认证终止验收](app-gateway-authentication-termination.md)，修复握手拒绝退化为 EOF 的实际缺陷，现标为已验证。下文保留本批当时的范围与未覆盖记录；B08 完整退出/换号仍开放。

对应 B09，并补充 B08/B16 已有的认证代次隔离。业务 HTTP 客户端此前只把 401/403 转成业务授权错误，不会通知认证 actor；即使刷新凭据已经失效，App 也可能继续显示已登录。本批将业务 HTTP 接入已有的认证状态观察流程。

## 请求与凭据使用同一个会话边界

`V2SessionHTTPAuthorization` 同时提供业务客户端需要的凭据和 HTTP transport。App 激活账号时固定 `V2AuthSessionEpoch`，把同一个值作为这两个依赖传入公共身份查询、本人资料、设备会话、群邀请、媒体上传、媒体下载解析和资料视图客户端。Push 的现有 convenience initializer 也复用此边界，退出清理仍使用单独的清理代次。

凭据获取前后、发送前及收到响应或传输错误后均复核账号代次与任务取消。旧账号请求不能获取新登录的凭据，其迟到成功、401、403 和网络错误不能作为新账号的结果返回。HTTP 边界没有实现刷新 transport 的协议，避免把刷新请求递归接回自身。

## HTTP 状态的处理

| 情况 | 行为 | 凭据与业务请求 |
| --- | --- | --- |
| 业务 401，发送使用的 token 仍是当前 token | 加入认证 actor 的共享刷新 | 原业务请求只发送一次 |
| 业务 401，当前代次已安装后继 token | 忽略前驱 token 的过期拒绝 | 不重复旋转凭据，返回原 401 |
| 刷新成功 | 持久化后继凭据，保持登录 | 返回原业务 401，由业务调用方决定重试 |
| 刷新 401/403 | 现有刷新合同判定终止，清除凭据并发布认证终止快照 | App 观察者进入重新认证流程；删除失败使用既有待清理状态 |
| 业务 403 或其他非 401 状态 | 保留该业务响应 | 不刷新、不清除凭据 |
| 断网、刷新 503 或无效响应 | 返回可重试错误 | 保留凭据与持久刷新 operation ID |
| 凭据存储暂不可访问 | 暂停认证，等待显式存储恢复 | 不把受保护数据不可用解释为撤销账号 |
| Task 取消或 `URLError.cancelled` | 返回 `CancellationError` | 不因取消清除凭据 |

边界不会自动重放写入或一次性媒体授权请求。刷新成功后的原调用仍可能显示业务授权失败；调用方的现有重试、幂等键和生命周期继续拥有重试决策。这一点是当前合同，不宣称所有 HTTP 操作都能无感重试。

## 共享刷新只完成一次

原实现让每个等待者都执行 `finish`。首个等待者处理可重试失败后，其他等待者发现没有活动刷新但仍有 pending operation，误抛 `sessionInvalidated`；若后续重试已复用该 operation ID，旧等待者还有机会再次修改当前刷新状态。

现在 actor 持有的共享 Task 在持久化和网络执行后只调用一次 `finish`，等待者只读取该 Task 的最终结果，并在返回成功前检查代次。终止删除、状态发布和重试失败处理因此只有一个所有者。持久 operation ID 的复用、先保存 pending 再请求、先保存后继再报告成功的顺序未改变。

## 验证与限制

本批负向验证分别复现：业务 401 未触发刷新与重新认证、两处 `URLError.cancelled` 分类错误，以及每种可重试失败下 32 个并发调用者中 31 个误收到会话失效。修复后的定向 **37 项 / 5 套件**通过；最终 **ClientKit 384 项 / 59 套件**、**App 183 项 / 17 套件**全套通过。

新增测试覆盖业务状态分类、刷新终止/成功/无效响应/503、凭据锁定、两个 HTTP 边界的原生取消、任务取消后的迟到 401、换号后的迟到结果与凭据获取、同代次前驱 token、并发刷新失败，以及受保护存储恢复后先保存 pending 再发 HTTP。App 组合测试使用真实业务客户端、刷新 HTTP 解码器、认证 actor 和状态观察者，分别验证刷新 401、403、503 的呈现结果。

存储恢复测试初版遗漏 `retryCredentialStoreAccess`，却等待本应被暂停的 HTTP 请求；该测试运行被主动中断（exit 130），补上恢复步骤后通过。它不是生产持久化缺陷，本批没有据此修改存储重试策略。

前一批 HTTP transport 使用受控替身和合成凭据；后续已补[本地原生账号与真实 URLSession HTTPS](live-account-https-authorization.md)四项验收。App 界面与实时 Gateway 的完整链路仍未覆盖。既有 ClientKit 全套继续包含消息替换 owner 夹具，本批没有重新运行服务端或生成新 owner 夹具。Protocol 27、PostgreSQL 25 与 SQLite 173/5 未变。
