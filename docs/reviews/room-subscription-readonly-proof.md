# Room subscription read-only proof

Snapshot/page use one physical transaction in REPEATABLE READ READ ONLY. Isolation is installed before the timeout setup SELECT establishes a snapshot. The existing physical-loan watchdog, cancellation, rollback and close/join remain in charge. Write calls retain their existing room and exact activation row locks; the default transaction mode is unchanged.

The first lease observation, room high-water, membership revision, historical membership rows and page log rows share the same MVCC snapshot. Exact owner shard/epoch, activation epoch, host and host incarnation must match. Missing room, mismatched token, null/expired lease or corrupt/non-contiguous log fails closed. clock_timestamp() is sampled again after decoding to reject expiry during the read. No reader locks the room/lease write fence.

Repeatable Read alone cannot observe a retirement committed after its snapshot. After the cut commits, a separate Read Committed transaction checks the exact token and DB clock again. A retirement, replacement or owner change committed during the cut is rejected. Remaining lease is min(cut initial proof, cut final proof, fresh proof), less the entire monotonic call elapsed time, rounded up. Thus a concurrent renewal cannot give an older cut extra authority, and pool/query/decoding/commit latency gives no lease credit. Caller-side grant RPC elapsed and gateway query-start anchoring remain required; this is a duration, never a transported clock deadline.

This proof linearizes before a retirement that commits after the final observation. It does not promise instantaneous Gateway revocation. The prior locking reader also lost its lock at transaction completion, before remote consumption. Planned retirement must stop/join Owner delivery before releasing its DB lease; Gateway must retain exact activation/fence plus conservative local expiry. New activation cannot refresh an old activation's deadline. Reordering lifecycle release before Owner close would invalidate this argument and must not be treated as a read-layer optimization.

Batch leaseProofs observes committed room H and exact live activation in one statement per at most 256 tokens, with no membership query/body read/row locks. Its duration subtracts elapsed over the entire batch call, including earlier chunks. Missing/expired tokens produce no proof. Owner renewal must obtain this through trusted composition, validate exact active binding, consumed H == proof H and all permission-control acknowledgments; it cannot accept a caller-supplied proof or authenticate new members with it. Concurrent commits after a proof are ordered after that observation and require the existing controls/dirty-head recovery.

Real PostgreSQL tests retain an uncommitted writer's exact activation fence while snapshot/page/proof read the old committed membership and H without waiting; after commit both change together. A controlled cut permits DB retirement to commit while the read is suspended, then requires the fresh proof to reject. Existing source tests reject expired and wrong incarnation tokens and verify historical membership cuts. Tests are submitted to root for execution; this agent does not build or start services.

PostgreSQL specifies that Repeatable Read freezes visibility at the first query and later reads do not see concurrent commits: https://www.postgresql.org/docs/16/transaction-iso.html . Transaction isolation must be set before the first query: https://www.postgresql.org/docs/16/sql-set-transaction.html . These rules are why both early isolation setup and a separate fresh proof are necessary.
