# D02：共享 App 启动与 Push 恢复

D02 为实施中。App delegate 初始化时创建并持有唯一 `V2AppStore`，同时绑定 token receiver 和 wake handler；SwiftUI 根页面使用这个实例。生产与 debug 测试域选择移至 App 启动配置，避免后台启动和页面启动打开不同账号目录。页面 `onAppear` 不再负责注册 Push 入口。

## 恢复所有权

`V2SessionRestoration` 为 MainActor 所有者，scene 和 Push 共享同一个恢复任务。调用方取消或等待期限到达只移除自己的等待，不取消其他调用方需要的恢复。恢复所有者本身有 25 秒工作期限；到期取消任务、结束等待，但直到底层操作实际返回才释放所有权，避免不可立即取消的磁盘回调与新恢复重叠。

App 恢复在打开及激活前检查取消和认证代次。普通 signed-out 不因 Push 再读旧凭据；持久退出标记仍先于会话恢复检查。恢复失败的受保护数据状态保留，前台按原路径重试。所有者取消不能强制中断已进入的原生磁盘调用，本机测试不证明真机磁盘收尾上限。

## 后台与前台

App 初始活动状态为 false；只有 scene 进入 active 才启用完整前台任务。后台恢复可以组装账号 runtime，但不会启动消息索引、全量会话刷新、Push 设置执行器和完整实时循环；这些在进入前台后启动。

Push 回调开始记录绝对 25 秒截止，恢复等待和增量同步使用同一个截止。同步 runner 使用剩余时间与自身预算中的较小值，不能在恢复结束后重新获得完整 25 秒。发起同步的调用者在截止后等待自己的连接排空；加入已有同步的短期限调用者可以独立结束，不关闭其他调用者的连接。flight 由工作所有者完成后释放，不能由一个取消的等待方清除。

## 验证范围

新增 App 测试直接构造 delegate 并调用系统回调适配器，全程不创建 View，验证已绑定共享 store、无凭据结果和 completion 一次完成。共享恢复测试覆盖一个 Push 期限到达而 scene 继续、单个取消、所有者超时后迟到回调和下一次恢复。客户端测试覆盖扣除恢复耗时后的截止、连接排空、短等待方不关闭已有同步及后续重启。

直接 delegate 测试使用无凭据测试模式，不代替真实已登录无 scene 的系统后台启动。真实 APNs、带凭据无 scene Push、锁屏/首次解锁、初始化阶段文件保护失败及系统 completion 时限仍需验收。真实登录与冷启动 UI 回归只证明原认证路径的回归情况，不充当 Push 验收。精确结果见本批证据记录。

## 本批结果

最终客户端报告 408 项 / 63 套件，实际执行 404 项，4 项在线测试按条件跳过，耗时 4.705 秒。App 在 iPhone 17 / iOS 26.2 的 192 项 / 18 套件通过，耗时 4.837 秒。独立原生 HTTP/Gateway 验证另执行 4 项真实 HTTPS（2.658 秒）和 2 项真实 App 认证终止/冷启动 UI（48.952 秒），持久结果为 9|3|0|0|3；两张冷恢复截图均显示退出后的登录表单。专用模拟器及私有数据库/证书目录删除已另行确认。

初次客户端完整回归中，短截止测试的 2 秒总耗时断言实际为 2.952 秒而失败；隔离原测试在 0.096 秒通过。最终将未扣减的原始预算设为 30 秒，保留 50 毫秒剩余截止，完整并发回归容差与既有网络测试一致为 5 秒。连接排空、游标不推进及后续重连断言未放宽。失败、隔离和最终日志均保留，见[证据](../../docs/reviews/verification-records.md#20260906-shared-app-restoration)。

最终复核另补前台会话刷新、Push 设置启动两个 await 后的认证代次检查，防止退出/换号后继续启动旧 runtime；最终 192 项 App 回归包含该改动。上述真实 UI 回归在此末尾检查之前执行，没有重复跑 UI；其余启动/恢复实现相同。

后续已补[真实凭据的无根页面入口验证](headless-push-entry-contract.md)：独立 delegate/store 经实际 Keychain、HTTPS/TLS 与 SQLite 完成恢复、重放和远端撤销；这不等同于系统无 scene 冷启动。该批亦重新运行了最终前台代次检查之后的真实 UI 回归，具体结果与失败修正过程见链接。
