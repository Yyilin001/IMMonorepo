# 旧媒体入口授权与供应商兑换边界

对应 B03/B04，延续[消息引用授权](message-reference-visibility-contract.md)。本批保留既有无 message location 的入口，并补齐其授权；protocol 27、PostgreSQL 25、SQLite 173/5 不变。

## 消息与头像

旧入口曾仅凭当前成员身份及仍存在的用户投影授权附件。成员离开期间发生编辑、随后重入，而个人投影尚未更新时，旧正文投影不能证明对当前内容版本的权限。

消息分支现在复用不可变接受记录、当前成员和当前编辑版本受众检查，同时要求有效媒体引用、未撤回消息及本用户仍有效的消息投影。投影的 room scope、消息 ID、房间 ID 与消息行一致，媒体 ID 必须出现在该投影中。共享状态本身不是访问凭据。标准大小写 UUID 拼写均可匹配，避免合法随机 UUID 被旧字符串比较误拒绝。

头像仍使用独立的当前 profile 可见性和双向 block 规则。同一对象若确为可见头像，不会仅因其另一条消息不可见而被拒绝。两条分支均要求请求设备有效、请求者 profile 处于 active 状态且账号未 disable。

## 兑换与租约

申请 grant 和原子领取均使用同一授权谓词。供应商签发地址后，PostgreSQL 完成兑换还会再次检查授权，并以 session/media/user/device、原 claim token、claimed 状态、未过期 grant 和未过期 lease 条件更新。更新不到记录必须报错；不能把无效的空更新当成功返回地址。

领取期间、供应商返回后、数据库完成后均检查取消和当前时间。已过期的地址不会从服务返回；已取消的领取不会继续调用供应商。若数据库已经完成消费后才取消或过期，保留 consumed 结果但不返回地址，释放操作不能将其恢复为 pending。旧请求的释放也不能清除已经由另一个 token 接管的租约。

供应商 I/O 不持有数据库事务。账号、内容和设备复核是最终消费语句的授权检查；本批不声称跨库所有撤权操作都与该语句严格串行化。已经返回的供应商 URL 仍遵守其有限有效期，不提供对象存储侧即时撤销；完整 owner/access epoch 与生产 provider 合同仍需后续验收。

## 验证

首次负例暴露了合法 UUID 拼写误拒绝，使 24 个数据库场景在基线 grant 阶段失败；同次独立单元测试复现供应商返回后忽略过期/取消。先修复 UUID 比较，再运行负例，才复现后续历史授权、缺失接受记录、账号/设备/投影变化以及租约失效/接管。测试中的 profile 非法状态同时改为 schema 允许的 suspended，并用精确错误断言避免把 SQL 夹具错误当授权失败。

真实数据库场景覆盖共享/inline 投影、正常附件、头像独立授权、issue/claim/provider 三个阶段的历史缺口与缺失接受记录、供应商期间设备撤销、账号 disable、profile suspended、投影移除、租约过期/接管及 grant 过期。假时钟和受控回调驱动时间变化，不依赖真实等待。单元测试覆盖领取、供应商返回、数据库完成三个边界的过期/取消，并核对供应商调用次数及完成/释放记录。

最终扩展回归 **307 项服务端测试 / 28 套件**通过，耗时 276.806 秒。包含 30 个旧媒体真实数据库场景、6 个领取/供应商/完成边界场景以及既有 HTTP、头像、按消息定位媒体、历史授权和跨 owner 回归。

最终日志、脚本和源码哈希见[本批证据](../../docs/reviews/verification-records.md#20260906-legacy-media-authorization)。本批未修改 ClientKit/App，未重新运行其测试；服务端分层回归不替代真实 App 到 TLS、生产对象存储、设备、Linux 或完整多 owner 迁移验收。B03/B04 保持实施中。
