# 房间生命周期发送与只读结果恢复

## 边界

普通发送依赖唯一房间实例、房间顺序执行与在途工作退役等待。正常释放不是立即删除实例：Host 先停止接单，等实际执行与 SQL 回调结束，关闭 executor 后释放租约。消息、完成凭据、必要投影与投递事件仍在同一事务中提交；提交确认后通过原 TCP 连接返回 accepted。

该实现采用本次会话明确的范围：普通内存权限发送不再提供逐事务的旧 Owner/activation 数据库写围栏。租约过期跨节点接管、迁移与旧进程恢复需由生命周期接管机制保证，不能把删除围栏解释为这些故障仍已完全覆盖。

## 实现

- `PostgresV2MessageSendOperationStore` 普通内存权限路径移除批量操作锁、Owner 行锁、activation 行锁及 SQL 核对，保留本地执行身份校验。对应 scalar 隔离回退使用内部运行时生命周期 scope，防止回退重新引入相同 SQL 围栏。
- 普通好友单聊的 typed accepted 消息复用房间首次加载的成员、禁言与权限判断；Owner 预检不再读取或锁定成员/禁言行。仍读取事务中的消息序号、准入计数及配对投影事实，这是当前写入分配/投影一致性的输入，并非重新查询好友或拉黑权限。
- 幂等依赖房间、发送者、客户端消息 ID 唯一约束。正常合并路径先插入；冲突使本事务回滚，隔离回退读取原结果。近期结果缓存仅在实际提交后更新。
- Gateway 结果恢复通过房间数据路由直接读取 Owner 数据库，使用 interactiveRead 准入，不激活房间、不占用房间消息队列、不获取执行/操作锁、不开启写事务。查询只读取本人对应的持久化结果并校验两个内容指纹。
- 查询不到返回 unresolved。客户端只发送 query；原提交期限内可用原 ID 重试，期限后保持结果待确认并进入 needsAttention，用户可恢复查询。查询超时与数据库错误不表示发送失败。
- 旧协议 closeIfAbsent 对发送消息解释为 query，不再制造 closed 回执。停止新增 message_operation_closures，移除 message_send_completions 的关闭围栏触发器。历史关闭记录及其不可变保护保留，以免破坏已有结果；其他业务操作的关闭语义未改变。
- 保留成功完成记录与 operation receipt：前者由消息日志/幂等使用，后者含客户端操作指纹和原始响应，客户端重试及恢复仍有实际消费者。普通当前权限路径无授权证明写入；旧控制授权、陌生人额度、特殊账号和群聊复杂路径仍保留相应业务流程。
- 跨房间批处理已有命令数、房间数与收集等待上限；本次没有任意降低这些上限。移除独立围栏减少跨房间持锁范围，但必要写事务仍可能使同一批次中的房间共享等待。

## Schema

当前新库使用 `IMV2/sql/schema.sql`。已有库在旧进程排空之后执行 `IMV2/sql/migrate-message-send-query-recovery.sql`，只删除旧发送关闭触发器及函数，不删除历史数据。服务启动和运维 schema contract 均要求旧触发器已移除，避免旧触发器悄悄把 advisory lock 加回热路径。未对用户已有运行数据库执行升级。

## 验证

- 服务端 12 个相关测试函数通过，Actor 生命周期 2 个函数通过（含参数化案例）；日志 `/tmp/imv2-send-lifecycle-tests-r6.log`。
- 客户端发送工作 10 个测试函数通过，包含成功响应丢失后重启恢复原 ID；日志 `/tmp/imv2-send-query-client-tests.log`。
- 好友/非好友、普通/预借连接、直接/collector 准备路径均覆盖。好友接受后隐藏 activation、成员、禁言表，普通发送和已提交结果查询仍成功；查询 absent（包括旧 closeIfAbsent）不写关闭记录，随后原 ID 能成功。
- 同 ID 并发仅一条消息、不同内容冲突、回执 INSERT 注入失败使消息/完成记录/序号一并回滚、COMMIT 不明不提前更新成功缓存、策略变更与房间 drain/release 等检查通过。
- 新 schema 安装与运维 contract 返回 true，重复执行转换脚本后 contract 仍返回 true；仅使用自建 disposable 数据库。
- `git diff --check` 通过。本次未跑全仓库测试。

最终 Release 构建通过，日志 `/tmp/imv2-send-lifecycle-release-r2.log`。压测器只同步结果查询语义及真实源码 SHA256，未修改正常发送速率、尝试上限、超时与测量时长。10,000 在线 / 1000 msg/s 同配置压测证据目录 `/tmp/imv2-send-lifecycle-10k1000-20261006-r31/candidate`。

Owner 事务正文均值本轮降低约 41.7%。P95 是十二个进程各自百分位的范围，并非合并后的全局百分位，不把这些范围折算成精确的全局延迟改善百分比。前后为两次同配置单次运行，仍存在运行噪声，未做重复实验置信区间。

临时 PG 和压测进程已按 runner 清理；未升级用户已有数据库。保留的性能热点是事务设置/提交、必要序号及准入状态、配对投影和消息写入。Owner 正文加借连接等阶段均值不能直接推导端到端延迟。
