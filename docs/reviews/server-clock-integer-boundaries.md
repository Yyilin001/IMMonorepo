# 服务端账号证明与 Gateway 时钟整数边界

2026-09-07，B01 的一批实现与验证。协议 27、PostgreSQL schema 30、SQLite 173/5 不变。

## 已复现的问题

账号证明签发直接把服务端时钟计算出的毫秒转换为 Int64。注入 NaN 后，独立测试进程实际触发 `Double value cannot be converted to Int64` fatal error。Gateway Hello 和心跳也存在直接转换。这里的输入是服务器时钟依赖，不是已证明可由远端报文控制的时间戳。

## 实现合同

- 账号证明签发检查当前时间和有效期相加后的时间能否精确表示为向零取整的 Int64 毫秒；编码后的截止必须仍晚于当前时间。异常抛出 `invalidClock`，不饱和、不截断溢出值，也不签发已经过期的证明。
- 验证先检查签名与声明结构，再检查服务器时间。合法证明遇到异常时钟报 `invalidClock`；伪造证明仍报 `invalidAssertion`。
- 凭据 HTTP 签发把 `invalidClock` 映射为空正文的 503，并设置 `Cache-Control: no-store`、`Pragma: no-cache`。其他既有验证错误继续走原有 401，签发服务不会被调用。修复前反例实际得到 401、无缓存控制和非空正文，三条断言失败。
- Gateway Hello 在修改协商状态前检查时钟；认证后请求在登记请求 ID 和额度准入前检查。心跳在异步准入返回后重新取时并检查，异常沿已有失败清理路径释放请求关联。同一个 Hello 或心跳请求在时钟恢复后可以成功。

## 验证范围

新增测试覆盖 NaN、正负无穷、正负最大 Double、Int64 毫秒上界，以及当前值可表示但加有效期越界、过短有效期、正常小数毫秒、真实 HMAC 验证、准入前和准入期间时钟失效。最终服务端定向回归为 **57 项 / 7 套件，6.387 秒**，包括 Gateway byte stream、账号证明、密码路由、凭据路由和旧档案取消路由。

首次最终回归启动因沙箱无法写 Swift 缓存而未编译，随后以已授权缓存权限完成；该日志与两份修复前反例均保留。证据见 [manifest](../../docs/reviews/verification-records.md#20260907-server-clock-boundaries)。

真实 HTTPS **5 项 / 2 套件（2.734 秒）**、App UI **2 项（64.268 秒）**、独立后台入口 **1 项（1.298 秒）**通过。验证正常登录、凭据签发、Gateway 认证及设备撤销后的界面与重启行为；数据库设备/撤销/有效 access/有效 refresh/事件计数 **16|7|0|0|7**，注册取消记录 **17|16|2**。专用 PostgreSQL/证书根目录及模拟器已独立核实移除，Gateway 清理后连接数为 0。本批未新跑完整 ClientKit/App 单元套件或历史数据库迁移链，没有真机时钟异常注入验收。

## 尚未覆盖

这批不证明其他数据库时间绑定、恢复 DTO、计数递增、全部时钟消费者或系统时钟回拨策略已经完成审计。B01 保持实施中，47 项仍为 16 已验证、31 开放。
