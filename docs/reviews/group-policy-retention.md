# 群权限与幂等回执保留

## 实现合同

当前 PostgreSQL 合同以规范 schema 为准。`group_role_policies(room_id, role)` 保存角色已明确配置策略这一事实，`group_role_permissions` 保存该策略允许的权限。两者都没有行时使用领域默认权限；存在策略标记而权限集合为空时明确禁止该角色的所有可配置操作。owner 继续遵守不可修改的 owner 权限合同。

设置策略在原来的 room lock 事务中写入标记、替换权限、递增房间策略 revision，并提交源事件和操作回执。标记每个房间、每个可配置角色至多一行。housekeeping 仍可按原保留期限清理 `group_permission_operations`，不再承担当前授权状态的存储职责。

普通权限 resolver 和三处批量消息授权查询均读取当前策略；优化查询同时检查已有非空权限行，避免没有标记的旧数据被误当成默认允许。普通发送、转发写入及群管理命令通过已有的统一授权函数读取相同策略。

## 新库初始化

新环境使用 `IMV2/sql/schema.sql`，直接创建角色策略标记、权限和不可变回执约束。
不执行历史权限回填或版本升级，正常回执 GC 不能删除当前授权状态。

## 验证范围

集成用例包含默认权限可发送、明确清空权限后拒绝、真实回执 GC 后继续拒绝，以及已有权限缓存/批量路径的再检查。当前验收保留缺少角色约束时两种启动门禁拒绝；历史升级测试已删除。

历史记录中 20 项服务端测试、3 个套件通过；源码指纹、失败/成功日志及完整 filter 见 [验证记录](../../docs/reviews/verification-records.md#20260906-group-policy-retention)。该修复不等于完成 B06：客户端群管理效果去重、按对象版本排序、snapshot 负状态、旧 payload 与 staging 迁移仍需完成。wire protocol 23 与 SQLite 结构在本批没有变化。
