# 回复、置顶与共享历史内容授权

对应 B03/B04。此批修复普通消息引用与共享内容读取的接受记录依据，不改变 protocol 27、PostgreSQL 25 或 SQLite 173/5。

## 写入边界

回复此前只检查目标是否存在于同一房间；置顶此前只检查目标存在且未撤回。当前权限和管理角色不能证明操作者见过原消息或当前编辑版本。

新回复、置顶及取消置顶均在原 owner 事务内检查：当前成员身份、原 accepted 成员区间、当前编辑版本的成员区间。三个区间独立判断；退群重入者可以引用过去已见且未被不可见编辑替换的消息，不能引用离开期间的编辑。没有明确引用版本的命令按当前内容版本授权。回复额外拒绝已撤回目标，置顶继续要求有效消息。已存在置顶不会提前返回 no-op 绕过授权。

目标房间锁沿用已有 room → admission/message 的顺序；成员变化、编辑、撤回的同房间写入受同一房间锁约束。回复和置顶的授权失败与写入在同一事务中，不新增消息、事件、操作回执或容量消耗。已提交操作的幂等结果仍在新的目标授权之前恢复，后续退群不改变原提交结果；这不是重新执行一次引用。

## 不可变接受记录

回复和置顶复用转发读取、源 export、转发最终接受与按消息定位的媒体下载已有的可见性谓词。原成员版本统一来自 `message_send_completions`：按消息的 room/sender/client-message 既有主键定位，再复核 message ID、room sequence 与合法版本。物理 `message_row`/`room_event`、兼容列或当前成员版本都不能替代该事实。

编辑受众继续由当前 message revision 对应的 `message.edited` 事件证明，使用已有唯一版本索引；不增加新的热写索引。缺少接受记录、绑定错误或缺少当前编辑证据时拒绝新读取/引用。本批没有实现缺失历史接受记录的自动回填；手工构造的旧迁移测试须提供真实写入同样会提交的接受事实，并分别验证缺失时拒绝及补齐后允许。

## 验证范围与剩余问题

负例覆盖普通群与 hybrid 群的回复/置顶、新加入成员、离群期间编辑、撤回目标、缺接受记录、正文存储兼容列漂移、重入和提交后退群重放。修复前 32 个参数场景记录 32 处问题；修复后该组和 15 个按消息定位的媒体下载场景通过。扩展版本还覆盖可见编辑、已存在的隐藏置顶和错误接受身份，并检查迁移夹具及两个索引的查询计划。

最终扩展回归 **292 项服务端测试 / 25 套件**通过，耗时 300.472 秒；44 个引用场景及既有媒体、转发、迁移、索引计划与 owner 边界均通过。

最终日志、源码哈希与脚本见[本批证据](../../docs/reviews/verification-records.md#20260906-message-reference-visibility)。本机 owner/SQL 回归不代表真实 App 到 TLS 的端到端验证。没有修改客户端；本批不重复引用过去的 ClientKit/App 通过数作为新验证。

B03 的旧缺依赖恢复、独立无正文撤销、完整房间目录/基线、账号/access epoch 响应栅栏仍开放。置顶控制事件和引用 ID 不是正文读取凭据，其他读取入口仍应逐项审查；旧的未按消息定位媒体接口及其退役/兼容范围未在本批关闭。B04 的全局封禁、跨 owner 完整迁移及保留清理继续开放。

后续已补旧媒体入口的历史授权、UUID 拼写及供应商兑换完成检查，见[旧媒体授权合同](legacy-media-authorization-contract.md)。其多 owner 迁移及统一响应栅栏仍未关闭。
