# 账号限流策略、计数与日期绑定边界

对应 B01。本批检查账号密码失败、账号 edge 预算和公共身份查询限流，修复配置与数据库类型不一致的问题；B01 其他入口仍开放。

## 确认的问题

三类限流策略缺少完整时长上界校验，部分还接受正无穷。启动配置会把 Int.max 秒转为 Double 并接受；密码失败阈值也能超过 PostgreSQL integer 的最大值。新增负向测试在旧实现上报告 18 个未拒绝的配置/策略用例。

当前锁定的 postgres-nio 1.33.1 在 Date 的非抛错编码器里，将相对 2000-01-01 的秒数乘以 1,000,000 后直接执行 Int64 转换。仅验证时长为正或有限，不能证明生成的日期可编码；即使当前日期和时长各自可表示，相减后的截止日期也可能越界。这里依据实际依赖代码确认风险，没有把配置负向测试说成真实驱动崩溃测试。

密码失败表的 failure_count 是正 Int32。锁定期限先于计数窗口结束时，原实现继续对已达 Int32.max 的计数加一，可能使写入失败并回滚新锁定和审计。

## 实现

| 入口 | 处理 |
| --- | --- |
| 三类限流窗口、密码锁定时长 | 构造时要求正值且微秒时长可精确转换为 Int64；无穷、NaN、越界值在启动前成为配置错误。合法分数秒和较大可表示时长保持不变 |
| 密码失败阈值 | 限制为 1…Int32.max，与 SQL 列一致 |
| 密码失败计数 | 在 SQL 整数上限饱和，仍重新写入锁定和审计。阈值判断不放行；这不是版本号、序号或操作 ID 的截断 |
| edge 预算消费、公共身份预算消费 | 先验证当前日期及相减后的截止日期，再交给 PostgreSQL 编码器 |
| edge 过期限流记录清理 | 同样验证实际截止日期，非法值不进入删除 SQL |
| 密码失败写入 | 验证实际当前时间、窗口起点和锁定截止时间；失败时事务不提交 |

共享内部检查函数匹配驱动的实际 Date 编码表达式，使用 `Int64(exactly:)`，并排除 PostgreSQL 正负无穷的保留整数。它检查的是编码范围，不把任意可编码日期承诺为 PostgreSQL 日历范围内有效；其他数据库日期错误仍由现有抛错路径处理。

## 验证

最终 **29 项 / 5 套件服务端回归通过（6.543 秒）**，包括三个真实 PostgreSQL 场景及密码/公共身份 HTTP 路由、配置边界测试。首轮 25 项通过后，补充了清理路径与日期运算后的越界场景，再执行最终集合。

- 真实 PostgreSQL 将失败计数分别置于 Int32.max−1 和 Int32.max，锁定已过期但窗口尚在；每个场景四路并发拒绝请求后，计数保持 Int32.max、账号被锁定、对应审计恰好一条。
- NaN、正无穷、极大当前日期，以及当前日期可编码但减去窗口后越界的组合，均在 edge 消费、edge 清理和公共身份查询中返回 unavailable；两张预算表保持无写入。
- 既有跨实例共享预算、不同地址隔离、窗口到期恢复、匿名键持久化和过期清理通过；公共身份 429、账号停用及密码成功/失败锁竞争回归通过。
- 配置测试验证五个相关环境变量的 Int.max 输入被拒绝；策略测试验证时长上下界、保留有限分数秒以及最大的合法失败阈值。

测试结束后确认专用数据库没有残留 im_v2 schema，并停止本次启动的专用 PostgreSQL cluster。没有修改协议、schema、依赖版本或部署配置。没有新跑 ClientKit/App、实际 TLS、生产 Linux 或多副本部署验收；这里的并发实例共享同一本地 PostgreSQL。

原始失败与成功日志、执行脚本、依赖检查及源码摘要见[本批证据](../../docs/reviews/verification-records.md#20260906-account-rate-limit-boundaries)。B01 继续实施中，仍需审计其他恢复 DTO、worker 计数和日期绑定。47 项总表仍为 15 项已验证、32 项开放；原始日志的干净 checkout 分发仍按 E08 跟踪。
