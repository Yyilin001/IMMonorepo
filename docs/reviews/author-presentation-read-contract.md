# 作者资料批量读取合同

## 批次与授权

Dispatcher 将不同连接的需求组合为一个最多 100 个资料键的读取批次，每个连接的输出仍受
16 条及帧字节预算约束。生产组装只调用 `V2ResourceProfilePresentationService.readMany`，
不为每个接收者调用完整服务。HTTP 单接收者读取也是同一流程的一项输入。

控制查询的合批窗口与执行容量等待分别计时。独立单接收者调用默认等待 3 毫秒合批，
合批窗口最多 5 毫秒；已有多接收者批次无需再等一个合批窗口。已准入工作等待 SQL
槽位最多 100 毫秒，且始终受调用者原始截止约束。不能仅因槽位短暂占用超过合批窗口
就返回一秒限流。全局仍最多四个实际 SQL 批次、400 个待处理键及 256 KiB 待处理字节；
队列已满时立即拒绝，等待到期时清理对应调用，取消不能提前释放实际 SQL 槽位。

可见作者延期准入本身不启动依赖重试间隔。待处理键和活跃键负责阻止重复准入，只有
领取实际读取槽位时才开始普通一秒重试间隔。因此未开始读取就排队过期的项，在容量
释放后仍可恢复；已经读取的临时失败或未确认结果继续遵守间隔，不能形成紧循环。

读取保留调用方的绝对截止时间。Dispatcher 的 500 毫秒投递预算贯穿批量控制查询与房间
权限读取，服务层不能重新授予十秒预算。房间原生 pin 分别给出工作截止和已捕获的授权
有效期：SQL 与返回前检查使用前者；成功读取的证明使用后者，且不超过节点资格期限和
30 秒上限。短请求预算不能让已下发资料在几百毫秒内失效，较长授权窗口也不能延长请求。
SQL 结束后的退休/资格检查、取消与真实工作排空义务均保留。

同批接收者的请求截止独立生效。共享读取和 SQL 使用本批仍有效调用方中最晚的原始截止，
不因较早接收者过期而取消其他接收者，也不重新计算任何接收者的预算。每轮控制查询前
剔除已过期项，返回结果映射回原输入顺序；过期项不能进入后续控制查询、构造展示许可或
交付。只剩过期接收者的房间上下文不再复核；同一上下文仍有有效接收者时保留完整证明
进行一致性比较。房间工作在十六路并发窗口中排队后，实际发起 RPC 前再次按上下文
原始截止筛选，RPC 仅使用本房间仍有效上下文的最晚截止，不能借用其他房间的预算。
Dispatcher 按各自截止丢弃迟到结果，整体 watchdog 在最后一个原始
截止到达时取消；取消和过期都不能提前释放尚未结束的 I/O 槽位。过期计数按接收者去重，
已经消费的批次结果不会在整体 watchdog 触发时再次计为过期。

读取流水线已满时，排队过期检查使用最早截止的保守下界，不为每个新兴趣重复扫描
整个待处理队列。新增请求或同连接新增键缩短截止时，必须先降低该下界并更新唤醒。
移除请求允许留下偏早的唤醒，但不能留下偏晚的唤醒；到期扫描重新计算剩余下界，
队列清空时移除它。此调度优化不能延长请求截止或提前释放实际读取/写入槽位。

可选写入明确区分已入队、暂时拥塞和永久丢弃。只有仍活跃且尚未入队任何字节的拥塞
结果允许重试：复用同一份编码、序号、许可时间和原始截止，在既有输出字节预算内最多
延后四次，间隔为 10 / 20 / 40 / 80 毫秒。重试等待不占实际写入槽，其他就绪输出可
越过它；同一连接仍保留活跃键，不能为这份数据重新查资料。重试不能越过原 500 毫秒
截止，页面/连接/刷新代次变化照常丢弃。NIO 通道不另建资料队列，正文积压仍优先。

重试保留原 `serverViewAgeMilliseconds`，接收端继续扣除准备后的排队和传输时间，
不能因重发而延长展示许可或头像下载期限。只有实际入队且客户端确认的结果允许去重。

每项接收者读取最多覆盖 8 个授权上下文；成员和审批是同一房间的不同上下文，私聊按目标
分别计数，关系名片不占房间查询预算。ClientKit 与 Dispatcher 复用 Core 的分批选择器，
超出单批上下文预算的完整键留待后续读取，不能把整个列表限制为 8 个用户。键的去重始终
包含上下文，同一用户在不同房间、关系和审批场景中均独立保留。

批次执行三轮控制面读取：捕获账号/设备/双向屏蔽/关系与资料版本，结合房间证明构造候选，
头像准备后再次验证。三轮各自保留所有输入接收者的顺序与独立失败；一个设备撤销不能借用
同批另一设备的身份。群昵称证明按 actor、room、context 分组，成员关系、路由与权限代次
须在交付前复核。同一批次按房间组合多个观察者，最多 100 个目标检查项通过一个
`profileVisibilityCohort` Actor 调用传输；单观察者仍使用原单人集合查询。跨房间最多
16 个实际调用并行，取消或原截止到达后停止补入新调用，已启动工作必须真正排空。

内部 Actor 会话协议升为 2，调用方和 Host 同步切换，不接受版本 1 会话。批量请求仅允许
同时具有 `userRoomCalls`、`roomCoordination` 的服务 principal；普通用户 principal
不能携带多个观察者。输入逐项校验真实用户、同房间及唯一目标，累计目标最多 100。
控制侧设备、关系及双向拉黑检查仍逐接收者执行，不能因内部服务身份而跳过。

单人资料集合、多人集合及其证明使用固定 Protobuf 字段；不接受这些分支经通用
`cold_value` 值树编码的旧形式。证明完整保留原请求、activation、成员/权限版本、目标
子集、群昵称及精确观察/截止时间。解码拒绝未知字段、缺失子消息、非法集合与混合房间
观察，控制侧仍按原请求逐项复核。资料请求与证明的内存预算直接计算全部保留字段，
不为计费执行反射遍历或序列化；畸形或超限模型也不能漏计集合中的值。

房间资料读取以一条 SQL 的已提交快照同时核对持久数据归属、成员、权限和群昵称，
不获取写入行锁，也不额外执行事务控制语句。未提交的并发写入只能留下完整的旧快照；
下一次读取必须看见已提交的新版本，或因归属变化拒绝旧令牌。原生 activation pin 贯穿
物理 SQL 与返回处理，退休后拒绝发布；物理连接的绝对截止、取消和实际排空要求不变。

房间资料 SQL 按请求中的观察者和目标分别进行相关成员查找，避免每个百项批次扫描
完整群成员表。每个查找最多保留两条当前有效的成员代次；一条代表正常匹配，两条
足以证明持久状态存在歧义。外层每个请求至少返回一行，额外匹配使精确行数校验失败，
不能用 `LIMIT 1` 隐藏重复有效成员。已退出的旧代次、未来加入和上下文规则仍按同一
房间快照过滤，查询不改变成员授权或所有者围栏。

房间 lane 继续按保守的模型驻留内存成本准入，资料轮次最多 64 KiB、100 个目标检查项。
该预算不是编码后的网络字节数；SQL 输入 JSON 不超过 64 KiB，查询行的 JSON 表示不超过
256 KiB。房间回复以当前固定 Protobuf 编码（包含回复信封）的实际大小检查 256 KiB 上限，
不再为未使用的 JSON 回复表示重复编码；源端和接收端均检查，运行时模型驻留
内存预算仍单独计费。一个 cohort
占用一个命令信封，内部目标全部计入轮次成本；可与相邻单人资料信封合批，但不能穿越
消息或写入屏障。Factory 展开检查项后执行同一 SQL 快照，再按原信封和观察者顺序拆回。
拒绝观察者也返回带版本的空证明。调用方校验数量、原请求、目标子集及共同房间观察，
防止缺项、换序或其他接收者结果被借用；不能据此假定跨网关所有查询只产生一次 SQL。

头像准备对同批 mediaID 去重，使用所有相关有效授权中最早的到期时间。Protocol 53 的头像
描述必须包含稳定内容身份、摘要和 byteCount；临时 download plan 可缺省。签名故障保留
可信内容描述和独立展示许可；元数据读取失败可以省略头像，不把已核权的昵称改成拒绝或
整项重试。取消仍向上传播。签名过程不持有数据库事务锁，最终权限复核仍必需。

## 展示与字节读取

使用作者流的页面在 `activateVisiblePage(delivery: .authorStream)` 中原子登记接收意图，
再向可见行暴露激活令牌。不能依赖另一个协调器任务及时启动来阻止 32 毫秒合批窗口
提前触发 HTTP。接收意图不授予展示权限；每项需求仍保留创建时的有限回退截止，
缺失流、重连或 nonce 更新均不能无限推迟它。独立 HTTP 页面保留原准入行为。

展示许可与下载计划分别映射为单调时钟截止。下载计划过期只移除计划，不移除头像内容
描述；服务端的已确认资料提示也只受展示许可截止约束，不能因为下载链接过期重读资料。
Protocol 53 不接受缺少 byteCount 的旧描述，计划存在时其大小和摘要必须与描述一致。

ClientKit 的个人/群头像资料仓库生成不可由 App 构造的 `V2AvatarReadGrant`。它绑定当前
页面、账号、不可变内容及展示许可，读取前后重新检查仓库状态与持久版本下限。缓存文件
或调用方给出的描述均不能构造展示权限。字节缓存命中无需有效下载计划；未命中时才检查
下载计划截止，缺少计划返回需要更新下载目标的错误。URL 轮换不改变内容缓存键。

页面失效、撤权、账号关闭或内容更换之后，旧 grant 不能通过已有文件句柄再次借用图片；
异步授权检查返回后仍需复核账号代次与内容身份。已经借出的文件租约保证解码期间文件不
被删除，UI 则在解码完成后再次核验展示授权，失效结果不得进入界面。新的展示许可不能
延长旧解码任务捕获的截止时间。头像字节故障不会撤销独立有效的昵称展示。

缓存未命中且计划缺失、过期或被字节入口拒绝时，App 通过仓库的 `refreshAvatarReadGrant`
复用既有资料批量鉴权队列；不在图片 View 内另建网络客户端。旧展示许可保留原截止，
刷新也受同一账号、页面、关系、成员和权限检查。同键等待共享一次读取，已经更新的计划
可直接复用；仅移除过期 URL 不算刷新完成。资料键有 2.1–2.5 秒随机刷新间隔，明确的
服务端限流仍需遵守；取消后非协作读取继续占用原槽位直到真实结束。

一次图片尝试最多主动刷新一次计划。页面最多进行四次延迟字节重试，使用退避、抖动及
服务端最早重试时间，之后等待正常展示重新授权；离开页面会取消等待。图片重试时间和
展示截止分别保存，等待图片期间仍有效的昵称保持显示，展示到期必须清除旧快照。刷新
网络错误或暂时未签出链接不撤销已有展示许可；明确拒绝、认证失效、页面关闭和版本过时
仍使旧 grant 失效。所有新结果再次经过现有代次与版本栅栏。

## 授权观察版本与拒绝

从 Protocol 51 起，展示许可和拒绝结果均必须包含 `authorityVersion`，不再接受只有 lookup key
的拒绝。版本由控制域的提交序号、可选房间 ID、成员修订和房间权限修订组成；它只是
排序依据，不是客户端可提交的授权凭证。返回值不包含拉黑方向或拒绝原因。

控制查询在同一 SQL 快照读取共享变更 head，以及关系和两个拉黑方向的持久修订。
三轮检查既比较当前事实，也比较持久修订，因此“拉黑后取消拉黑”不能因最终状态相同
而绕过检查；其他用户推进全局 head 不会使事实稳定的整批请求失败。拒绝也经过最后
一轮设备、关系和房间检查，不能跳过交付前核权。

Room Owner 对不可见结果返回带房间修订的空集合；缺失或不带版本的证明按可重试处理。
缺少私聊路由时可以返回无房间的拒绝，新建路由后可向有房间的版本前进。Schema 75 将
待审核申请的加入、移出和目标变更与房间权限修订原子提交；取消后重新申请会推进版本，
即使成员版本和公开资料都没变化。申请说明文字修改、幂等重放不推进该权限版本；回滚同时
撤销推进。数据库启动与规范 schema 检查校验此触发器的启用状态、执行方式和函数正文。

## 持久安全失效与本地展示

`profile_invalidation` 只接受显式 `hidden`、`suspended` 或 `deleted`，不接受缺失状态或
`active` 的旧普通更新格式。它只推进账号本地的安全版本下限，不触发批量资料补查。
普通名称/头像更新仍由当前作者兴趣和显式上下文读取完成。

该下限不因收到新资料、不可用响应或清空展示缓存而删除；快照准备阶段与已有下限取较大值，
在 ACK 前完成合并。活动资料必须严格高于安全下限，同版本活动资料不能推翻拒绝。
迟到的私聊身份投影在下限处被消费但不能恢复身份或授予房间事件访问。

本地展示行保存可检查的资料修订，实时失效只清理不高于下限的行。读取时在同一个数据库
事务中关联当前失效表，因此快照原子换表即刻遮蔽旧展示，不依赖插入触发器重放，也不在
ACK 后增加全表清理。快照准备与激活之间接受的更高版本展示仍可保留。持久名称与头像
下载授权的有效期继续分别处理；这些本地事实不能授权受保护字节下载。

## 共享内容缓存

控制查询只读取当前授权事实、资料版本、头像引用和接收者自己的备注。公开 handle、昵称
和账号种类按 `(userID, profileRevision)` 在进程内共享。首次缺失批量读取，同键并发等待
同一任务。版本变化必须重新加载；旧版本内容不能与新版本授权事实拼接。

缓存不保存设备状态、拉黑关系、房间资格、私人备注、展示许可或资源下载能力。已经预热的
内容仍需通过每轮当前授权查询才能返回。加载期间资料变更导致旧版本不存在时，当前请求
可重试；不把这种竞态写成永久拒绝。缓存最多 2048 项、4 MiB 内容，最多 4 个加载任务，
每任务最多 100 个键，单项最多 16 KiB。该范围是实例内，不是跨进程全局缓存。

## 取消和关闭

一个页面离开不能取消同批仍有效的其他接收者。每次页面激活都有服务端内部 generation，
即使重新使用同一客户端 nonce，旧批次也不得交付到新页面。所有参与者离开或最早批次
期限到达才取消共享读取；不合作的依赖仍占用真实任务槽直到返回。

控制查询的批量队列按总键数、编码字节和任务数量准入；服务层最多保留 512 项接收者工作，
每设备最多两项。Runtime 先排空入口、Dispatcher，再关闭资料服务及依赖。缓存任务关闭
必须等待实际加载完成，不因调用者取消而提前释放数据库生命周期。

## 验证与剩余范围

真实 PostgreSQL 聚焦回归覆盖预热内容后的设备撤销、两个方向的屏蔽、资料版本变化、
签名期间账号/关系/资料/成员变更、上下文隔离和生产 Runtime 读取。结构化测试证明
100 项输入共用三轮控制端口调用、一次头像准备，100 个待处理连接共用一次批量服务调用。
这些计数不包含首次公共内容缓存加载，也不代表万人群容量或任意部署下的数据库总查询数。

已确认可见资料的读取前去重见[接收确认合同](author-presentation-receipt-contract.md)。完整
变更失效边界、队列容量调整与万人端到端验收继续按
[完整实施计划](../proposals/author-presentation-implementation.md)推进。
