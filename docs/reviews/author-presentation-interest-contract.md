# 可见作者集合合同

## 协议与权限

Protocol 54 使用独立 `AuthorPresentationStart/Started`（137/138）建立当前连接的资料视图。
请求绑定已协商 stream 和客户端 view nonce，可以携带最多 8 个消息房间，也可以不带房间，
供列表页使用。消息房间只选择已获准投递的消息可提供哪些作者提示，不授予成员资格或资料
访问；群事件订阅不再携带或结束作者 nonce。服务端在启动回执完成写入之后接受该视图。
可选分发器的注册名额耗尽时，启动返回可重试的 `AUTHOR_PRESENTATION_UNAVAILABLE`，
不返回成功启动回执；普通消息订阅和心跳继续工作。

`AuthorPresentationInterests` 请求 135 和回执 136 携带完整的 `(userID, context)` 集合及递增
序号。context 显式区分关系名片、私聊目标、房间成员和入群审批；每次最多 128 个唯一键，
同一用户的不同上下文分别保留。空集合表示全部移除。序号必须在正的有符号 64 位范围；
旧序号、其他连接和旧 nonce 不能覆盖当前集合。回执表示处理完替换，不是资料授权或消息
游标，也不使已结束的视图重新激活。delta 与 ACK 同样使用完整键，不再携带单一房间。

Gateway 校验 stream、方向和载荷后，先由 Dispatcher 处理，再写回执。非空集合通过
正常命令 admission，客户端也使用普通读取额度，因为新增作者可能启动读取。空集合与精确页面结束一样属于清理，
不需要额外的域准入额度。服务端仍按账号、设备和房间上下文调用资料授权端口；订阅
声明不证明请求者有权查看这些作者。

## 可见性与生命周期

客户端资料仓库为可见行引用计数，同一完整键出现多行或跨页面只占一个资料键。
整个账号仓库最多 128 个唯一资料键、512 个行引用；超限显式拒绝，不截断已准入的
可见快照。同一用户的不同资料上下文分别进入集合，不再按消息房间过滤。
离屏快照的引用标记为可回收：当前可见行需要名额时，优先回收没有实际可见行的最早
缓存键；回收最后一个缓存引用会移除兴趣，已发出的展示期限不能因此延长。实际可见行
不会被缓存挤出，释放已回收的旧引用也不会撤销新行。缓存准入失败不丢弃本次有效展示。

作者集合有独立于 UI 失效流的观察者。订阅和初始信号在同一个 actor 操作内完成；
后续信号最多保留一项，消费者始终读取完整最新集合。初次发布立即执行，滚动变化
合并 25 ms。视图续期重新发布所有页面的完整集合；递增序号不跨 nonce 复用。

连接级 PageCoordinator 最多接纳 16 个页面和 8 个消息房间，统一拥有接收、可见集合
发布和续期三个结构化子任务。列表页不建立房间订阅，聊天页另外持有普通群事件租约。
加入页面会结束旧视图并生成新 nonce；已有页面只保留原截止内的许可，新页面不能借用。
离开页面先撤销该页作者许可，再等待实际请求结束；其他页面的有效许可继续保留。
同一连接上的可重试服务错误、请求超时及本地暂时过载只结束本次接收，已有页面保留
尚未到期的展示许可；重试退避与新 nonce 不能延长原截止。明确拒绝、不可信响应、
页面退出或连接代次变化仍撤销，等待重试期间到期的许可不能继续展示。
独立资料启动失败不能撤销普通房间订阅；房间权限变化、账号连接代次变化会立即废弃旧
资料绑定。列表与聊天页都在后台停止，前台重建；suspend 完成前不准入新页面，close 后
立即拒绝新准入，同时等待已有实际 I/O 结束。慢依赖不能把请求带到新连接。
TLS 发送边界再次检查当前连接、stream、view 和本地期限；启动时还核对完整消息房间集合。

## 服务端索引

Dispatcher 同时维护连接到作者集合、作者到连接集合的反向索引。最大关系数由
连接上限乘以每视图 128 个完整键界定；页面替换、精确结束、连接移除和 runtime 关闭
清理对应关系。查询反向索引时排除已到期的页面。stream 唯一性使用独立 Set 检查，
注册不再扫描所有已连接客户端。私聊目标读取解析出的权限房间也进入房间反向索引；
后续该房间的权限变化能够重读对应私聊键，移除键时同时清理这项映射。

新关注关系先登记，再进入既有有界批量资料读取。初次读取未获队列准入时关系仍保留，
服务端保留刷新义务并轮转重试，客户端已有的有界补齐也能恢复初值。

## 持久资料和关系变更

Schema 74 引入、当前 `im-v2-current-76` 保留：公共资料 outbox 和 `author_presentation_control_changes` 共用
单行 `author_presentation_change_head`。序号分配与业务修改在同一事务；head 行锁
保留至提交，回滚同时撤销序号分配，后来的发布不能越过尚未提交的变更。私人备注、
好友关系和两个拉黑方向通过 deferred constraint trigger 在提交阶段登记，避免先
占住 head 再等待后续业务行锁。此锁不进入消息发送事务。现有公共 outbox 的 claim/
完成字段与网关读取游标相互独立。

每个网关独立读取全部已提交变更，不会相互领取走事件。一次查询在同一数据库快照下
读取 head 和最多 128 条后续记录，来源只包含作用域、用户与版本，不携带展示授权或
私人备注正文。备注事件只路由到所属账号的设备；关系与拉黑变化分别使双方已有的
可见资料重新核权，不向客户端披露拉黑原因。公开资料、私人备注、关系及两个拉黑
方向保留独立的版本下限，重复事件不能恢复旧读或吞掉其他来源的刷新义务。
启动先取得 head 边界，再开放连接。日志清理造成缺号、游标超出 head 或首次连接源时，
重读当前可见作者并移动到 head；重置不清空已有消息，也不创建全群用户资料请求。

反向索引在初次读取前登记。事件提高对应作者的最低资料版本并撤销压缩指纹；已开始
的读取携带刷新身份，只有身份仍匹配且结果达到最低版本才可发送。取消兴趣也使旧读
失效。事件到达前已开始的 writer 可能完成，但不能清除新义务；同连接的新版本等待
它结束后发送。已安装的有效资料或拒绝同时满足 writer 成功与客户端确认才移除义务。

一个 runtime 拥有变更读取任务。空闲轮询间隔 100 ms，积压时继续读取，来源失败退避
500 ms 并继续重试已有义务；来源未追平或失败时暂停读取前去重。每轮最多检查 1,000 个连接，每个义务至少间隔 1 秒重试；
实际读取、输出和写入沿用共享有界队列。队列拒绝不删除义务，不为每个群成员建立
任务。关闭会取消并等待真实来源调用，再关闭 ingress、dispatcher 和资料读取依赖，
即使底层暂不响应取消也不提前释放依赖。

## 群昵称来源

群昵称复用 Room Owner 已提交的 `group.nickname_changed` 事件。Gateway 仅在已认证
房间投递入口解码一次有界的群、用户和版本，再进入同一个有界 ingress；没有群昵称
正文或授权缓存。事件只刷新该群内仍关注该作者的页面，清空昵称仍携带其非零版本。
群昵称版本下限独立于公共资料和私人备注，初次读取期间的变更会淘汰旧读取结果。

昵称变化和消息资料提示共用 offer、键、字节预算及一个实际消费者。同群同用户合并
到最高版本；容量不足时留下一个固定大小的全局重读标记，不能静默丢弃失效通知。
关闭时清除排队项并等待实际消费者退出。

## 房间授权和缺口恢复

房间订阅的有序 lane 在真实接受新投递、完成 socket 授权投影后观察资料变化；重放只
返回原投递确认，不重复通知。完整基线（分段时为最后一段）、grant/revoke、授权失效、
缺少正文的 head 和授权序列缺口都登记该房间的重读义务。已有在线接收者为空也不能
跳过事件观察。成员修改、角色修改和角色权限修改的持久房间事件同样使该房间重读。

房间重读只通过新维护的 room→连接索引访问仍有有效页面的连接，不扫描所有房间。
离页、连接移除和关闭清除索引。重读撤销旧提示和正在读取的刷新身份，但保留各内容
版本下限；新内容仍经过资料服务逐接收者核权。房间重读与昵称变化共用 ingress 预算、
合并和溢出恢复，不能阻塞消息正文。此机制尚不替代客户端已有安全失效路径，完整
生命周期与授权期限边界仍按整体计划验收。

## 版本化拒绝与客户端恢复

HTTP 与 TCP 使用相同的权限观察版本。每个完整 lookup key 保留已授权版本和拒绝下限，
按控制、成员和房间权限三个计数器分别比较；无法直接排序的拒绝合并各维最大值。恢复
必须达到全部拒绝下限并严格前进，单独提高公开资料或昵称版本不能恢复权限。相同内容
在权限恢复后可以直接重新展示，不必等待重开页面。

较旧的拒绝不能撤销较新的已安装或暂存授权；不同页面的候选也不能遮住另一个页面的
已授权下限。忽略旧 HTTP 拒绝时，其仍在等待的原请求返回过旧结果，不会一直挂起，也
不会借用别的页面的展示授权。版本化拒绝不设置只能靠新页面解除的永久因果栅栏。

拒绝记录最多 2,000 个，和普通短时负缓存分开。容量溢出保留保守的页面因果栅栏，新
页面重新建立观察；退出账号或关闭仓库清空。临时不可用仍不写成拒绝，暂存候选淘汰也
不能删除拒绝版本下限。旧本地失效接口保持原有因果防护，待新机制承接完整边界后删除。

## 验证与剩余范围

测试覆盖 128 作者边界、空替换、重复作者、非法序号、错误方向和 foreign stream，
以及真实编解码/连接发送、Gateway 回执前登记、清理时准入耗尽、多行引用、跨房间
隔离、乱序替换、旧页面和取消时非协作请求。另有 10,000 个内存连接的索引边界测试；
它不代表真实 TLS、数据库或图片分发的万人容量验收。

服务端内部可见兴趣、刷新任务、版本下限和交付确认账本均以完整资料键计数；按用户的
反向索引只用于发现连接，不合并不同上下文的权限或版本。ClientKit 仓库支持一次接收绑定
多个既有页面，但每个页面分别获得 grant。加入页面需要新 nonce；解绑不会使旧 nonce
能够扩展到新页面。先到的候选资料记录尚未领取它的绑定页面，关闭一个页面不清掉其他
页面的候选与许可。第二个页面领取同一份资料不会使第一个页面正在读取的头像 grant 失效。

Protocol 54 提供多上下文 wire；账号级页面协调器合并最多 16 个页面、8 个消息房间，
列表和聊天页共用一组接收、确认、兴趣发布和续期任务。页面绑定和退出仍分别维护其授权。
当前代码与已完成的多页面验证见[完整实施计划](../proposals/author-presentation-implementation.md)
的“连接级多页面所有权子阶段”。完整失效边界、真实万人持续负载及故障组合仍需按该计划
验收；较小多网关集群中的头像变更及续期通过，不代表全部容量和故障场景已经通过。
