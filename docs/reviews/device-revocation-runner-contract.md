# 独立撤销执行与本地退出

日期：2026-09-07。B08 仍实施中。接续[持久交接合同](device-revocation-handoff-contract.md)，本批接通执行器与 App 前台生命周期，并替换退出前的 Push 网络清理。

## 执行与所有权

`V2DeviceRevocationRunner` 只依赖独立队列和目的受限 HTTP 客户端；不读取 AuthSession，不刷新或借用新账号凭据。一个 App 组装一个 runner，公开 run 拒绝重叠 owner。每批至多读取四条到期任务，逐条发送，单设备失败不阻止同批其他设备。

队列保存后发布有界通知；调度器先订阅再查询持久 nextAttemptAt，避免漏唤醒。空队列等待通知，有期限任务等待定时器；没有每秒读取 Keychain 的轮询。时间等待每分钟最多重查墙钟一次。被暂停的任务不自动发送。

- 204：删除对应完整任务，服务端已确认撤销。
- 410：服务端确认已识别证明的兑换期限结束，可结束任务；不宣称撤销事务已提交。
- 401/409：分别持久暂停为 invalidCredential/operationConflict。
- 网络、5xx、408：持久退避，从 2 秒增长至 300 秒；429 采用更长的 Retry-After，提示最多接受 86400 秒。
- 无效响应及其他请求错误：持久暂停，避免无限发送不可修复请求。
- 保存本地完成/失败状态出错：停止 runner，保留原任务，App 记录需要重试；再次前台激活可重开 runner。

所有结果仍以完整任务 CAS 落盘。取消后迟到响应不删除或变更任务；旧网络 flight 实际退出前，runner 仍保留所有权。新登录不等待该 flight。公开 run 的调用方负责取消和结果消费。

## App 退出

显式退出先保存文件意图并使旧认证工作失效，再关闭旧账号展示及工作，完成凭据到独立队列的交接、注册记录清理与文件标记清除。已移除 `removePushEndpointBeforeCredentialDeletion`：本地退出不需要另发 Push HTTP、刷新过期凭据或为删除端点打开 SQLite。服务端能力兑换事务负责同时禁用 Push 资格。

前台激活启动独立任务，即使当前 route 已 signedOut；后台只取消其任务，不等待网络后才允许其他生命周期工作。再次前台时如旧取消仍在排空，保留句柄，排空后再启动。App 销毁取消该任务。普通账号退出不销毁 App 级队列或执行器；测试专用作用域清理显式清除自己的队列。

## 验证与剩余范围

- ClientKit 439 报告、434 实际、5 在线跳过，68 套件通过；定向 16 项/2 套件验证响应丢失、持久退避、状态映射、设备隔离、自动唤醒、取消排空及本地完成失败。
- 正常签名模拟器 App 195 报告、194 实际、1 在线跳过，20 套件通过。使用从未在服务器签发、access 已过期的本地凭据执行真实 App signOut，得到 signedOut、凭据删除和原撤销任务；重建 App 后仍 signedOut，任务仍保留，最终清理测试域。
- 原生 HTTPS＋自建 PostgreSQL 5 项/2 套件通过。真实撤销已提交后丢弃客户端解码结果，队列保留 attempts=1；重建队列与执行器后用原操作重放并清理。兑换 HTTP 204×4、401×1、409×1，设备/撤销/禁用校验保持 7|3|0|0|3。这是客户端结果丢失注入，不是实际线路断包。
- 本批不证明后台 OS 调度、真机锁屏、任意指令处强杀或旧 Push 请求忽略取消时的物理网络退出上界。未新跑完整 UI/Gateway/headless 在线套件。
- 持久暂停的用户可见状态与显式恢复入口、App 前后台往返和换号期间网络 flight 的完整交互验收，以及注册响应迟到等 B08 剩余边界仍开放。本批不关闭 B08。

PostgreSQL 28、protocol 27、SQLite 173/5 不变；47 项仍为 16 已验证、31 开放。失败和最终日志、资源清理与源码哈希见[证据](evidence/20260907-revocation-runner/manifest.json)。
