# 注册取消 HTTP 边界

日期：2026-09-07。B08 仍实施中；承接[服务端仲裁](registration-cancellation-contract.md)。schema 29、protocol 27、SQLite 173/5 不变。

账号服务新增 POST /v2/device-credentials/cancel-registration，并加入生产组装的地址限流路径。路由位于普通账号认证之外，仍必须经过 trusted-edge secret 和客户端地址验证；不需要、更不会借用后来登录的账号凭据。

请求必须为 JSON，最大 1 KiB，且恰有 deviceID、operationID、proof、issueBeforeMilliseconds 四个字段。拒绝额外 userID（含 null）、账号令牌字段、缺失字段、错误用途证明、非法 UUID 或截止。服务端使用强类型请求调用既有事务仲裁；不能靠 device ID 本身取得撤销权限。

响应约定：已提交取消或幂等重放为 204，服务器确认签发或绑定会话期限结束为 410，输入不合法为 400，基础设施失败为 503。204 与 410 语义分开；路由生成的响应为空且 no-store/no-cache。中间件保留原有 403、429、503 及 Retry-After 行为，body collector 保留 413。

新 ClientKit 传输只接受完整原注册证明，没有 AuthSession 依赖。HTTPS 地址拒绝用户信息、query 和 fragment；默认复用禁止重定向、cookie、凭据缓存的账号 URLSession 适配器，请求超时 15 秒。重试原样编码四个字段，不生成新操作或截止；204/410 必须为空响应。429 保留合法非负秒数，其余错误不当成完成。URLSession 取消和取消后的迟到成功均继续抛出 CancellationError，保留上层重试责任。

验证包括路由及客户端的参数化输入/结果测试、真实 PostgreSQL HTTP pipeline 的先取消后签发拒绝与签发后撤销、事务失败回滚和持久限流。原生 HTTPS 账号服务测试在真正提交取消后丢弃客户端解码结果，再用原证明重放；数据库检查只有一条无账号的取消记录。后者是已提交结果丢失注入，不是物理线路断包或跨进程持久队列恢复。

当前 HTTP 签发仍未强制接收这份证明，App 也还没有请求前持久化及独立注册取消队列。真实数据库的签发后取消由新的服务端域入口建立绑定；HTTPS 验收只验证取消入口的实际部署组装与预签发取消记录。不能把这些证据称为“响应完全丢失的端到端恢复已完成”。下一步完成签发入口及 ClientKit/App 接线，再验收旧注册记录迁移、冷启动、换号和系统中断。

本批原始日志、计数及源码散列见[证据清单](evidence/20260907-registration-cancellation-http/manifest.json)。47 项状态保持 16 项已验证、31 项开放。

验证结果：ClientKit 完整回归 458 项报告、453 项实际执行、5 项在线跳过，72 套件（5.039 秒）；服务端 HTTP 单元 13 项/3 套件（0.010 秒）；真实 PostgreSQL 22 项/1 套件（29.356 秒）。首次服务端测试编译发现限流密钥初始化标签错误，修正后重跑通过，失败日志保留。

真实 HTTPS 5 项/2 套件（2.685 秒）通过：取消响应为 204×2、410×1、400×1；唯一取消记录计数为 1|0|1（总数/已绑定账号/已取消），原有设备与撤销计数仍为 7|3|0|0|3。在线测试夹具在完整离线回归后补充并单独在线验证，期间生产代码未改变。未运行新 App/UI/Gateway/headless 或真机验收；两个自建数据库根目录及证书均已清理。
