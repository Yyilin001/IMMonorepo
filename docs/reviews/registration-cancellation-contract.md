# 注册签发与取消的服务端仲裁

日期：2026-09-07。B08 仍实施中；本批为完整丢失签发响应恢复的服务端部分。

## 需要解决的竞争

只在客户端收到 access/refresh 后保存服务端撤销能力，无法覆盖响应完全丢失。只让客户端提前生成一个秘密也不够：取消可能在签发之前到达，查询“设备尚不存在”后返回，随后签发仍会成功。取消必须能留下阻止后续签发的持久记录。

新增 V2DeviceRegistrationCancellationProof 使用独立用途前缀和 256 位随机值，不可作为会话撤销能力、access token 或 refresh credential 使用。完整请求由 device ID、注册 operation ID、证明和毫秒级 issue-before 截止构成，必须在客户端首次请求前持久保存，后续重试原样复用。UUID 在边界规范化；截止在解码时验证，服务端首次接受时还限制为未来 24 小时以内。

服务端只保存这四个字段的带用途域摘要，不保存明文证明。取消接口将不接受 user ID；只有经过账号因子验证的签发事务可以把该摘要绑定到实际账号与设备会话。

## 事务实现

新 V2CancellableDeviceRegistration 要求可信注册的 device/operation 与取消证明匹配。PostgreSQL 先取得证明摘要锁，再取得既有账号锁和设备锁；签发截止在设备行锁取得后检查。取消和签发始终按相同顺序持锁，避免一个从账号锁等待证明锁、另一个反向等待的死锁。

取消先完成时，保存无账号的 cancelled 记录；相同证明的后续签发被拒绝。签发先完成时，设备行、access/refresh、服务端撤销能力、有限期加密重放、配额和取消证明绑定同时提交。取消随后通过绑定的账号及会话 created/expires 时间验证目标，调用同一条设备/令牌/Push/事件撤销 SQL，并与 cancelled 标记同时提交。失败不能留下“已取消”标记却保留活动凭据。

不同秘密、设备、操作或截止得到不同摘要。伪造请求可以取消它自己对应的未签发操作，不能占用或取消已知 device ID 的其他证明。已签发设备只允许一条实际绑定；更换证明不能取得既有操作重放。重复取消返回幂等结果，设备事件仍只有一条。

未签发请求超过 issue-before 后不能再创建会话。已经绑定的取消证明在 issue-before 之后仍然有效，直到设备绝对会话期限加 10 分钟结束；取消路径同样在设备行锁取得后读取时间。截止已结束不等同于本次执行了撤销。

## 存储与迁移

PostgreSQL 当前合同升级至 im-v2-current-29，新增 device_registration_cancellations。记录只允许“已取消且未绑定账号”或“完整绑定账号与会话”两种状态；已绑定设备有部分唯一索引。启动检查验证列、精确约束定义和有效唯一索引，版本号不能替代约束。

受控 28→29 迁移增加新表而保留已有凭据，不给历史操作补造取消证明。开发测试的旧迁移链追加该迁移；此变更没有执行生产迁移或部署。没有启用记录 GC：未来清理必须区分未签发截止和已绑定会话截止，不能在 issue-before 后删除仍可取消活动会话的绑定。该保留策略继续属于 B15/D04 的开放工作。

## 接线边界与后续验收

本批增加并验证可取消注册的服务端域入口。现有 HTTP 签发和 App 仍使用原入口，尚未因本批而获得完全丢失响应后的恢复能力；保留原入口是分阶段接线状态，不是最终兼容性方案。

后续必须让账号 HTTP 签发强制接收证明并经过可信账号验证，增加受 trusted-edge、限流与严格 body 合同保护的取消入口；ClientKit/App 在请求前保存证明，退出及冷启动把未接管操作送入独立持久取消队列。还需明确旧注册记录迁移、证明保存失败、截止后重新登录、正在被其他尝试接管的操作、客户端取消请求先到和实际线路丢包。不能只接上 HTTP 就关闭 B08。

本批验证结果与源文件散列记录于[证据清单](../../docs/reviews/verification-records.md#20260907-registration-cancellation)。protocol 27、SQLite 173/5 未改；47 项仍为 16 项已验证、31 项开放。

验证结果：Core 95 项/31 套件（0.006 秒）；原有 HTTP 单元 10 项/2 套件（0.009 秒）；真实 PostgreSQL 21 项/1 套件（28.843 秒），包括新增 4 项测试的 7 个参数场景、原有凭据/Push 及七条历史迁移链。独立 28→29 迁移保留种子访问凭据、拒绝重复迁移，并验证缺失唯一绑定索引和弱化绑定约束均无法通过启动检查。首次编译过滤器未匹配测试，只计编译成功。

当前 schema-29 的真实 HTTPS/原生账号服务回归 5 项/2 套件通过（2.743 秒），设备/撤销/有效访问/有效刷新/事件计数为 7|3|0|0|3。该在线链路仍走原 HTTP 入口，是现有客户端兼容回归，不是新注册取消接口的端到端证明。本批未重跑 App UI、Gateway/headless 或真机系统测试。所有自建数据库及证书临时根目录均已独立核实清理。
