# 作者资料接收确认合同

## 协议和所有权

当前协议通过 `AuthorPresentationReceipt`（帧 133）提交确认，通过同结构的
`AuthorPresentationReceipted`（帧 134）返回连接内处理结果。请求绑定当前认证连接的
`streamID`、连接视图 `viewID`、一个具体的 delta `sequence` 和最多 16 个唯一完整资料键。
Protocol 54 不再携带单一房间；同一用户在不同群、关系、私聊和审批上下文中分别确认。
序号必须为正且不超过有符号 64 位整数上限，必须携带实际保留条目的
最短剩余毫秒数，范围 0～300,000；零只表示已应用。确认不是累计游标，不确认丢失的帧。

此确认不授予资料或资源权限，不修改消息日志、个人同步游标或房间订阅。
它不需要业务查询或业务命令配额，但受正常连接帧、请求数、字节和会话期限约束。
客户端拒绝将确认发到已替换连接或已离开的页面。服务端拒绝未协商、错误 stream、
畸形载荷及客户端发送的响应帧；旧页面或已淘汰批次的有效确认只作幂等空操作。

## 客户端确认时点

资料接收器保留原 delta 序号。资料仓库完成整帧校验、版本下限读取和资料安装后，
只对当前绑定页面集合中实际持有、未过期且与该条目完全一致的展示资料返回确认。
从 Protocol 51 起，已安装到当前可见行且通过权限版本比较的有效拒绝状态也确认，避免服务端无休止重发同一拒绝；该确认不
授予权限。暂存候选、过期条目、旧版本和可重试结果不进入确认。
页面协调器再次检查生命周期，然后在原连接代次发送确认。仅收包或放入 inbox 不确认。
缓存淘汰或离开可见区域不会延长授权；当前缺失仍由有界资料读取恢复。

## 服务端确认与写入竞态

发送前保存有界的候选指纹，初始状态为未确认、未写出。客户端确认和实际 writer 完成
可以以任意次序到达；只有两者都成功，且原期限、stream、view、序号和作者仍匹配，
指纹才可用于省略重复内容。写入失败、取消、过期或页面离开不能产生已知资料状态。
新批次替代旧候选后，旧确认不能确认新批次。

可见作者的刷新义务同样要求实际写出与应用确认同时成立。变化事件会替换义务身份；
前一版资料的确认或慢 writer 完成不能删除后一版的刷新义务。拒绝状态被确认后停止
该次重试，但不能形成“已授权”的内容指纹。

指纹包含公共资料、群昵称、私人备注及头像内容身份；私人备注变化不能被公共资料版本
相同掩盖。确认不延长原许可期限，也不能创建授权。服务端把客户端报告的剩余时间锚定
在该 delta 的准备时刻，并取原服务端许可与页面期限的更早值；延迟或重复确认只能缩短
去重窗口。客户端计算剩余时间后到确认真正送达的耗时，不会被当作额外有效期。

## 因果计时与读取前去重

Protocol 54 的 delta 必须携带本页面在服务端已实际经过的单调时长，在记录 serverNow
之前采样并向下取整。服务端知道随机 nonce 的时间晚于客户端创建 nonce 的时间，因此
客户端只需扣除“本地页面年龄减去服务端页面年龄”。该差值仍包含初次上行等待、准备
后的队列等待和本次下行延迟；若服务端年龄超过本地年龄则拒绝。正常打开较久的页面
可以接收新产生的短许可，迟到帧不会得到一段新的完整期限，且不依赖设备墙钟同步。

读取前省略仅适用于仍在可见作者订阅中、没有待刷新义务、已实际写出并确认保留且期限
有效的资料。变更源应用到当前 head 后只开放 1 秒的省略窗口；已知积压、缺口或错误立即
关闭，读取停滞也会自然到期。接收变更、退出可见集合、换页和断线都撤销提示。没有这些
条件时仍调用当前授权 reader；读取后相同内容也只能在原保留期限内省略，不能续期。
`suppressedReads` 计数单位是省略的资料键，不能等同于数据库 SQL 次数。容量和完整失效边界仍按[完整实施计划](../proposals/author-presentation-implementation.md)验收。

## 验证范围

- Core：序号、数量和重复作者边界。
- ClientKit：实际保留条目、暂存/旧版本不确认、TCP 编码及已离开页面拒绝发送。
- Server：错误 stream/view/批次/作者不能确认，提前确认与成功/失败写入竞态，
  Gateway 认证方向和载荷边界，确认不调用业务 handler。
- 这些测试不构成万人群资料查库次数、生产数据库或端到端容量验收。
