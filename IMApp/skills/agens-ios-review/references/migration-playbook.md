# 迁移手册

当旧 iOS 代码需要朝 AGENS 风格规则迁移时，使用这份手册。

## 1. 识别现有异步形态

先判断当前实现主要基于哪一种：
- completion handler
- delegate
- notification
- GCD 编排
- lock
- 混合方案

不要一上来就重写全部逻辑。先识别边界和职责。

## 2. 决定目标桥接形式

- 单次结果：桥接为 `async` 或 `async throws`
- 重复事件：桥接为 `AsyncStream` 或 `AsyncThrowingStream`

桥接要集中在一个兼容层里完成，不要让每个调用方各自写一套临时 wrapper。

## 3. 先保行为不变

- 引入桥接层时，先保证业务行为保持稳定。
- 先把调用方迁到桥接后的 async API。
- 只有当调用方迁完之后，再清理回调嵌套、线程跳转和历史编排逻辑。

## 4. 再收紧隔离

行为稳定后，再做下面这些事：
- 把 UI 相关状态迁到 `@MainActor`
- 用 `actor` 或所有权重构隔离共享可变状态
- 用显式隔离替代“默认在主线程”这类隐式假设
- 重新评估跨异步边界的 `Sendable` 一致性

不要把 `nonisolated` 或 `@unchecked Sendable` 当成捷径，除非你能写清楚安全前提。

## 5. 明确处理取消

- 确保 async wrapper 能合理传播取消语义。
- 对流式任务或长时任务，在自然挂起点检查取消。
- 避免用户侧任务已经取消，但后台工作还悄悄继续运行。

## 6. 验证迁移结果

优先做针对性的验证：
- 现有单元测试
- 聚焦的 async 测试
- 针对回调顺序和 UI 状态更新的回归测试
- 仓库已有的 build 或 scheme 级验证命令

最后明确写出仍需人工确认的风险，尤其是和界面状态时序相关的问题。
