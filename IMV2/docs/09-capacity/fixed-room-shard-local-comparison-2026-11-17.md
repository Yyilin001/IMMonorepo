# 固定房间分片本机对照，2026-11-17

在一台 14 核、48 GiB 的 Apple M4 Pro 上顺序运行三个拓扑。使用原生 macOS Swift debug 服务端及压测器、PostgreSQL 16、独立的 Account 进程和三个 Placement 投票进程。后台有其他工作负载，各轮没有独占 CPU、磁盘和内存。数字适用于本次设备、软件构建和流量模型。

## 数据与负载

- 从同一份种子快照恢复两个用户库、两个房间库和控制库。固定 16 个用户和 16 个私聊房间，环状目标、轮流发送、128 字节文本、TLS 长连接。两个房间分片分别有 6、10 个房间。
- 双 Host 使用两个 Gateway/Room Host 进程，由指标核实各自执行 8 个房间。客户端固定连接第一个 Gateway，跨 Host 投递经过 Actor RPC。单 Host 时全部 16 个房间在本地执行。
- 双主库拓扑将含 10 个房间的分片放在第二个独立 PostgreSQL 实例上，控制库、两个用户分片和另外 6 个房间留在第一个实例。两个实例共用物理磁盘。
- 压测端使用 IMV2GatewayLoadGenerator，固定随机种子和轮转发送，调度频率 100 Hz。消息使用真实发送操作与持久化确认；业务负载未另加历史拉取、附件、重连或接收方延迟验收。
- 最终对照将设备和用户限速分别调到 2048、4096 条命令/秒，并将客户端每连接在途请求上限对齐 Gateway 的 4。压测端启用有界队列，排队时间计入确认延迟。测试库提高了房间及分片准入窗口额度。调整仅用于临时部署。

## 判定与读取明细

每档先预热 5 秒，再测 60 秒。最终对照要求从计划发送到收到 ACK 的 P99 ≤ 100 ms，计划消息未确认比例及服务端拒绝次数占线上提交次数比例各 ≤ 0.1%，测量阶段完整、无终止错误、连接失败或最终业务失败。另列窗口内实际 ACK/s 和阶段消息最终获得的 ACK 数，便于发现阶段末排队。两次达标表示该档经两次 60 秒窗口验证，不能外推到长时间峰值。

[逐档数据](fixed-room-shard-local-comparison-2026-11-17.csv) 中，default 是原设备限速下的 30 秒摸底。open 和 sustain 提高限速，客户端最多允许 8 条在途，分别测试 30 秒和 90 秒。aligned、cross、check、confirm 和 upper 均采用最终的 4 条在途、有界队列和 60 秒窗口。检查阶段包括从种子快照重建并重新签发测试凭证。阶段平均耗时取 Gateway/Room Host 指标的计数器差值；各阶段有嵌套，不能相加。采样缺失的单元格留空。

默认配置的设备限额为每秒 32 条命令。16 个发送设备在目标 800 条/秒时均出现 RATE_LIMITED。提高限额后，8 条在途的摸底中观察到 Gateway 的 connection_count 拒绝计数增长，而 connection_bytes、process_bytes、process_count 拒绝数为零。最终对照采用匹配窗口，避免将压测端超额并发误判为数据库极限。

## 两次通过的最高实测档位

| Room Host × PostgreSQL 主库 | 目标条/秒 | 两次窗口内实际 ACK/s | 两次计划发送至 ACK 的 P99 | 较高档位表现 |
|---|---:|---:|---:|---|
| 1 × 1 | 800 | 799.39、799.96 | 92、9 ms | 1000 条/秒时 P99 达 1894 ms |
| 2 × 1 | 1200 | 1199.97、1199.99 | 18、36 ms | 1600 条/秒两次均确认全部消息，P99 分别为 76、412 ms |
| 2 × 2 | 600 | 600.00、600.00 | 12、10 ms | 800 条/秒时窗口内实际确认 771.50 条/秒，P99 达 3771 ms |

表中三个通过档位均无服务端拒绝、漏确认或最终业务失败。复测后的数据库消息总数与原始 16 条加预热和测量 ACK 数一致，依次为 52016、78016、39016 条。

双 Host 单库的 1600 档复测中，线上提交至 ACK 的 P99 为 60 ms，从计划发送至 ACK 为 412 ms，尾部拥塞包含客户端调度和排队。双 Host 双库从 600 升到 800 时，采样到的房间队列平均等待从 0.043 升到 4.093 ms，房间消息持久化阶段平均耗时从 0.748 升到 4.909 ms。各轮共享机器且后台负载波动，尚无依据将双库的性能差异归因于 PostgreSQL 磁盘、网络或 CPU 中的单一因素。confirmupper 为双 Host 单库高档位复测。
