# 群容量等级与 100k 验收门槛

状态：当前代码合同；没有以成员上限代替吞吐实测。

## 创建与成员边界

群创建时按包含群主的初始成员总数确定不可变的 `capacity_class`。

| 初始成员数 | 容量等级 | 公共消息恢复 |
| --- | --- | --- |
| 1～5,000 | `standard` | 房间事件日志与授权游标拉取 |
| 5,001～100,000 | `large` | 房间事件日志与授权游标拉取 |

两类群都不为公共消息创建逐用户正文副本。后续成员操作必须遵守创建时容量等级的上限。
建群仍需让每个初始成员发现房间，因此建群发现事件与普通消息写入的成本不同。
`100000` 是成员拒绝边界，不是已验证的发送吞吐或服务延迟。

## 可靠性与维护

个人成员关系、会话状态和单侧活动使用可靠个人事件。暂时依赖故障继续重试，确定性失败暂停并审计恢复。
个人事件收据保留到用户分片迁移目标，来源已完成队列的回收不删除收据。
房间事件的可见性由当前成员身份和接受、变更时的权限事实共同决定。

## 验收要求

- 标准群和大群发送都只写房间正文与规范事件，不产生个人公共消息副本。
- 验证 5,000、5,001、100,000 和超限成员数，以及群主计数和重复成员拒绝。
- 验证离群、重入、新成员的历史访问、离线追赶和新设备快照恢复。
- 大规模建群验证分页发现、来源确认丢失后的去重及目标分片切换。
- 固定连接数、群规模和发送率，记录接受延迟 p50/p95/p99、数据库写行/WAL、后台 CPU 和补拉时间。

旧扇出预算类型仍在模型清理范围内；不能使用它们的配置值推导当前房间日志的容量结论。
