# 2026-11-05 手机账号多会话测试

## 场景与恢复

目标为一个真机接收账号、1000 个测试账号分别建立私聊，随机选取会话，合计 100 条文本消息/秒，持续 300 秒。发送端在 Mac 上运行，服务端保持消息顺序、可见性和持久化配置。

准备阶段发现两类独立问题：

- 最初故障表现为 Owner 安装不可用、账号订阅无法 Ready，并伴随旧集群路由记录；最初触发原因尚未完全确认。恢复过程中同时停止 Gateway 和 Placement，进一步导致 Host 无法提交退役；这是运维操作错误。通过吊销旧 Gateway 签名主体、排除旧容器、完成 SQL 会话结算并通过正常仲裁流程退役旧 incarnation 后恢复，没有删除 Placement 历史或修改房间 epoch。停止脚本新增退出码与 OOM 检查，必须确认 Gateway 正常退出后才能停止 Placement。
- 直接生成的测试夹具缺少双方的 `direct_room_profile` 初始投影事件。补齐幂等 outbox 事件后，真机已显示“压测会话”名称。此问题属于测试数据准备，不代表正常建聊接口缺失资料。

## 连接准备优化

`V2AccountRoomChangeService.install` 原先逐房间等待 Owner 安装。改为最多 8 个独立房间同时安装，单房间保留直接调用；底层订阅协调器仍负责全局准入。任务组退出前等待子任务完成，全部房间安装完成后才发布 Ready。保留成员撤销、引用清理、多设备共享与重试语义。

增加大账号初始化完成日志，包含房间数量、耗时与 Owner 重试次数，不记录账号标识或凭据。

一次优化前后真机重启抽样（约 0.5 秒轮询间隔，另含 SSH 与启动工具开销）：

| 观测 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 从发起 App 启动到首次观察到认证连接 | 1.636 秒 | 2.359 秒 |
| 从发起 App 启动到首次观察到账号 Ready | 7.514 秒 | 5.445 秒 |

优化后服务端日志记录 1002 个房间安装耗时 3415 毫秒，Owner 重试 0 次。这是单次抽样，不应作为稳定 P95 或 8 倍提速承诺。`slot` 指标覆盖内部阶段，不能与 `resolve`、`subscribe` 等阶段相加。

## 验证

- 账号订阅服务 26 项测试通过，含新增的并发上限与 Ready 时机检查。
- 房间订阅 Registry 29 项测试通过。
- 停止脚本 2 项测试通过。
- Linux Release 在 Mac 本机交叉编译；部署前确认 Gateway 退出码为 0，Placement/account/operator 保持运行。
- 部署后小流量预检 20 条消息全部确认，无发送失败、心跳超时或队列溢出。

## 正式发送结果

北京时间 13:34:11–13:39:47（包含连接爬坡、300 秒发送和排空）：

- 1000 个发送账号认证成功，30,000 条发送、30,000 条确认。
- 连接失败、业务失败、跳过消息、心跳超时、队列溢出均为 0；最大等待发送队列 2 条，结束时 0 条。
- 发送确认 P50/P95/P99 为 20/107/154 毫秒，最大 346.08 毫秒。
- 发送调度到确认 P95/P99 为 108/157 毫秒；这些不是手机展示延迟。
- 服务端最终核对全部 1000 个测试私聊，共 30,040 条持久化消息（包含两次各 20 条预检），与本轮发送量一致。
- 每 15 秒容器采样（含前后准备/排空）Gateway CPU 平均 61.1%、峰值 217.9%，内存最高约 214 MiB；PostgreSQL CPU 平均 30.3%、峰值 100.19%，内存约 2.2 GiB。Docker CPU 的 100% 代表占满一个逻辑核，采样峰值不是连续全程最大值。

## 手机接收验证边界

用户确认测试期间切换过后台或锁屏，不能把本轮视为持续前台接收测试。发送结束时复制的 SQLite 快照校验通过，但尚未追平：1000 个测试会话仅 19 个摘要、56 个消息投影最大序号与服务端最终序号一致，恢复队列还有 966 项。完整本地消息投影共 16,332 条（包含已有非测试消息）。

随后已恢复 App 前台，服务端记录 1002 房间 Owner 安装耗时 1876 毫秒、重试 0 次；再次获取手机快照时连续两次遭遇 CoreDevice socket 关闭，尚未确认最终排空结果。

发送确认、手机列表摘要同步、手机完整消息历史落地是不同验证口径。设备连接恢复后的最终核对：

- 暂停 App 写入后复制稳定 SQLite 快照，`PRAGMA quick_check` 返回 `ok`；运行中首次复制曾出现索引校验异常，稳定快照未复现，符合复制期间写入导致快照不一致的表现。
- 1000/1000 个测试会话的本地消息数量及最大消息序号均与服务端一致。
- 1000/1000 个会话最新摘要消息序号与服务端一致。
- 测试会话本地共 30,040 条消息，恢复队列为 0，核对后已重新启动 App。

结论：本轮发送、持久化以及手机最终补齐均通过；由于中途切后台，不能用本轮证明持续前台 100 条/秒的实时展示延迟，也未测得准确的补读排空耗时。
