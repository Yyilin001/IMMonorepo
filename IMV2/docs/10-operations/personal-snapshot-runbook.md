# 个人快照运维

状态：当前代码使用房间日志和可靠个人事件。项目尚未上线，新库使用 canonical bootstrap；不执行旧消息副本的迁移或回填。

## 数据与任务

个人事件进入 `user_sync_log`，载荷直接保存在必填的 `payload` 中。个人投影工作器维护成员关系、会话、单侧活动、收藏及个人设置，快照构建器直接读取个人投影版本。公共消息、反应和群公共事件通过房间日志恢复。

公共种类误入个人日志时，工作器暂停该用户并记录 `public_content_in_personal_stream`，检查点不前进。缺失或格式错误的个人载荷按失败策略处理。修复准确的来源与日志记录后，通过审计的 user-projection 重放操作恢复；不要直接推进检查点。

## 检查顺序

1. 检查来源个人事件队列的 ready、leased、scheduled 和 paused 状态，确认正确的来源分片。
2. 检查用户投影检查点的失败序号与错误码，确认事件属于个人状态。
3. 检查快照产物的构建状态、租约和失效时间；重试继续使用持久化分页进度。
4. 检查日志保留下限、有效令牌与回执。低游标通过快照恢复，不能伪造为当前日志头。
5. 分片迁移期间保留路由栅栏、个人事件收据和稳定幂等证据。

房间消息的不可变状态仍有压缩与回收任务。任务使用 maintenance 连接，按主库与已配置房间库 URL 去重创建；用户分片只维护个人日志与快照。消息状态容量从同一组房间库采集，用户分片指标不重复统计。`IM_V2_MESSAGE_PROJECTION_STATE_RETENTION_SECONDS` 控制安全保留时间；当前有效消息修订不能作为无引用状态回收。

## 已完成个人事件回收

来源队列在确认完成七天后回收，按 delivered_at 索引分批处理，每次最多 1,024 条。
保留期从目标提交后的来源确认计算，不从原事件创建时间计算；pending、leased 和 paused
事件不参与清理。任务与其他房间维护工作一样按实际房间库去重运行。

user_state_event_receipts 不随来源队列或个人增量日志一起删除。队列回收后重新入队的相同事件
仍由目标收据返回原用户序号，旧租约不能确认重新领取的工作；用户分片迁移继续复制收据。
