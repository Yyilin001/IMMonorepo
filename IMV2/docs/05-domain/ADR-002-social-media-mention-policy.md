# ADR-002：关系、媒体与提及的授权策略

状态：已接受（常规聊天基线）

日期：2026-07-23  
所有者：产品、安全、存储与客户端负责人

## 背景

V2 规范把关系、媒体引用和提及列入第二阶段，同时要求每个命令拥有
权威所有者、幂等键、明确授权、同步表示和失败恢复路径。规范已明确：

- 媒体字节不通过 IM TCP 传输；
- 附件与签名 URL 是受保护数据，不能写入 Push 或日志；
- 命令授权必须基于权威成员资格和策略，缓存不能在拒绝后继续授权；
- Push 只是隐私安全的唤醒提示，不能承担投递正确性。

但规范没有选择关系模型、屏蔽语义、媒体保留/下载边界，以及 @ 提及的
可见性和通知规则。这些选择会改变 PostgreSQL 约束、事件受众、同步投影、
审计范围和客户端离线行为；因此不得由实现自行推断。

## 必须决策

| 主题 | 候选策略 | 已接受结论 |
| --- | --- | --- |
| 关系模型 | 单向关注、双向好友、联系人、仅房间成员，或组合；关系建立/删除是否双边确认 | 双向好友：请求 → 接受/拒绝；任一方可删除好友。 |
| 私聊准入 | 谁可创建私聊；陌生人请求、同意、拒绝和撤回的状态机；关系删除后历史/新消息边界 | 好友可正常私聊。非好友也可发起私聊，但在接收方尚未回复或成为好友前，按发送方—接收方对实施可配置的滚动窗口条数限制；常规默认值为 24 小时内最多 3 条。接收方可将“接收陌生人消息”设为关闭，关闭后拒绝新的陌生人消息；屏蔽始终优先。关系删除不远程擦除既有本地历史。 |
| 屏蔽与静音 | 屏蔽是否阻止私聊、群内可见性、@ 提及、搜索、Push；静音是否仅影响通知 | 屏蔽是单向的：阻止双方私聊、提及和通知，不改变共同群的历史/新消息可见性；静音仅抑制通知。 |
| 群内提及 | `@all`、角色提及和个人提及的授权主体；已退出/被屏蔽/无权查看成员是否可被提及 | 活跃成员可 @ 活跃且可见的成员；仅 owner/admin 可 @all；无权目标或屏蔽结果不向发送者泄露细节。 |
| 提及通知 | 在线提示、离线 Push、红点/未读和静音的优先级；是否允许发送方知道被抑制 | 提及写入同步事实；在线提示/Push/红点遵从静音和屏蔽，发送者只收到命令成功，不得获知抑制原因。 |
| 媒体对象所有权 | 上传主体、媒体所属 room/message、可复用范围、引用计数和删除触发条件 | 上传者先拥有临时媒体对象；仅扫描通过后可在其有权发送的 room 中引用；每个已提交引用计数，撤回后阻止新下载。 |
| 上传与扫描 | 预签名上传流程、文件类型/大小配额、病毒/内容扫描状态、扫描失败和超时的终态 | 独立认证上传、类型/大小配额、异步扫描；`pending/failed/expired` 媒体不能进入消息；扫描失败或超时为不可引用终态。 |
| 下载授权 | 每次下载的授权边界、签名 URL 的 TTL/单次性、转发/撤回/成员移除后的访问规则 | 每次下载由认证设备授权、签发短 TTL 单对象 URL；撤回或成员移除后拒绝新签发，旧 URL 不作为撤销承诺。 |
| 保留与删除 | 未引用暂存对象、已发送附件、撤回附件、法务保全和导出的保留期限 | 未引用暂存对象在 24 小时后清理；撤回附件在 30 天后清理，除非未来法务保全规则另行覆盖。 |
| 隐私与审计 | 文件名、哈希、缩略图、关系和提及记录的日志/审计可见范围与保留期限 | 审计仅保留操作主体、对象 ID、结果与时间；不记录正文、原始 URL、令牌或缩略图内容。 |

## 已固定的工程不变量

- 关系变更、私聊准入、媒体引用确认和提及命令均使用独立 operation ID，
  以持久化唯一约束返回可重放结果。
- 陌生人私聊的配额由服务端权威计数并与消息提交在同一事务内扣减；客户端
  只能展示本地提示，不能决定是否仍可发送。接收开关、双向好友、目标回复和
  任一方向的屏蔽均由同一准入检查读取。默认开关为开启；关闭仅阻止新的陌生人
  消息，不删除已有对话或影响好友私聊。
- 媒体先由独立受认证上传服务接收和扫描；聊天消息只引用已授权、已确认
  的媒体标识，绝不内联媒体字节或对象存储 bearer URL。
- 消息提交时必须在同一 PostgreSQL 事务内确认媒体引用的可用状态、写入
  权威消息/事件/outbox，并保留用于重试和清理的状态；扫描、转码或对象
  存储失败不能留下可见但不可恢复的引用。
- 每次媒体下载和快照页读取一样，需要面向认证设备的、撤销感知的授权。
  成员移除、关系/屏蔽策略变化或媒体撤回后的处理必须由批准策略明确，
  不得依赖旧签名 URL 的自然过期来声称已撤销访问。
- 提及目标必须来自消息提交时的权威可见性集合；不得用客户端本地成员缓存
  扩大目标集合，也不得把被屏蔽、静音或无权查看关系的结果泄露给发送者。
- 提及、关系和媒体事件进入用户同步日志；Push 或在线 socket 仅作可丢失提示，
  不能作为已通知、已下载或已读取的事实。
- 原始对象 URL、访问令牌、媒体内容、私有关系和被抑制的通知决定不得写入
  日志、追踪字段、Push 负载或高基数指标。

## 批准后的实现门槛

1. 为每种命令写出状态机、权威 owner/shard、幂等约束、授权矩阵、并发与
   历史访问规则；对私聊和群聊分别说明。
2. 评审 Protobuf、Core domain、SQL、Gateway 和事件/sync 兼容策略；关系、
   媒体和提及不能以自由 JSON 旁路版本化协议。
3. PostgreSQL 集成测试覆盖重复提交、竞争关系变更、屏蔽、成员移除、扫描
   未完成/失败、签名 URL 过期、对象清理、worker 重试及 Push 丢失。
4. 客户端测试覆盖离线 outbox 重启、投影原子性、媒体下载授权失败、提及
   抑制和不泄露策略结果。
5. 安全审查通过后，补齐配额、指标、告警、对象生命周期作业、保留/导出
   流程和事件恢复运行手册。

## 备选方案、回滚与复审

本 ADR 采用常规聊天的“双向好友、受限陌生人私聊、单向屏蔽、群聊可见性独立、扫描后附件”模型，
且不把对象存储 URL 当作授权。若发现关系或媒体策略泄露可见性，必须停用相应命令和下载签发，保留
已经提交的审计/清理状态，并通过显式策略事件恢复；不能靠删除数据库行修复。
关系模型、媒体 provider、内容扫描、提及通知或隐私法规变化时必须复审。
