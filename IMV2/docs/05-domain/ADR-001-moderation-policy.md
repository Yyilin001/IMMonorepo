# ADR-001：审核与追溯处理策略（待批准）

状态：已接受（常规聊天基线）

日期：2026-07-23  
所有者：产品、安全与合规负责人

## 背景

V2 已能以保留身份与排序的 tombstone 撤回消息。规范同时要求审核、审计可见性和任何追溯性处理使用独立 ADR；普通异步 fan-out 不能隐式剥夺已经授权用户的历史访问。

本 ADR 只记录必须确认的决策，未批准前不得启用审核命令、追溯删除、远程擦除或角色扩权。

## 必须决策

| 决策 | 候选项 | 已接受结论 |
| --- | --- | --- |
| 操作主体 | 房主；管理员；受信任安全服务；人工审核员 | owner/admin 可踢出或禁言；受信任安全服务可冻结房间；人工审核员仅经独立后台授权。 |
| 可执行动作 | tombstone；隐藏展示；踢出成员；禁言；冻结房间 | 普通撤回为 tombstone；审核可踢出、临时禁言或冻结；不提供隐式远程擦除。 |
| 历史访问 | 仅阻止未来同步；显式 redaction 事件；合规保留例外 | 成员移除仅阻止未来同步；追溯 redaction 必须是显式事件并留审计。 |
| 审计可见性 | 仅安全团队；房主可见摘要；被处理者通知 | 房主/admin 仅见必要摘要；完整审计仅安全团队；被处理者收到不泄露举报人的结果通知。 |
| 申诉与恢复 | 不支持；人工恢复；有期限自动恢复 | 临时禁言可自动恢复；踢出/冻结仅由人工或 owner/admin 恢复。 |
| 保留与导出 | 审计期限、法务保全、导出授权范围 | 审计保留 180 天；导出仅安全团队，法务保全规则优先。 |

## 已固定的工程不变量

- 每个审核命令必须使用独立 operation ID，并持久化幂等结果。
- 权威状态、审核事件、审计记录、fan-out plan 和 outbox 必须由 PostgreSQL 同一事务提交。
- 任何 retroactive redaction 必须是显式、可审计的事件；不能依赖当前成员资格在异步 worker 执行时偶然变化。
- 设备撤销只能阻断后续连接、同步与历史获取；不能声称擦除已在设备上的数据。
- 审核或 push 失败不得使已提交的消息、同步日志或 fan-out plan 丢失。
- 审计日志不得包含访问令牌、密钥或不必要的消息内容；指标不得使用 room/user ID 等高基数字段。

## 批准后的实现门槛

1. Protobuf、Core domain、SQL 和 Gateway 错误映射同步评审。
2. PostgreSQL 集成测试覆盖授权拒绝、幂等重放、显式 redaction、成员移除后的历史边界和 worker 重试。
3. 客户端 outbox、同步投影和 UI 呈现均有终态/申诉可见性测试。
4. 运行手册、审计查询、告警和保留/恢复流程通过安全审查。

## 备选方案、回滚与复审

不提供审核能力、仅提供前向成员移除、或提供带显式 redaction 的审核是不同
产品方案；不得将普通撤回悄然扩大为追溯删除。批准后若发现授权/保留规则不
满足合规要求，应关闭审核入口并保留审计证据，不能删除既有记录。角色、历史
可见性、保留、申诉或监管要求变化时必须复审。
