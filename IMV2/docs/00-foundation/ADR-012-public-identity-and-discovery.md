# ADR-012：公开身份、联系人发现与目录边界

## 状态

Proposed — 2026-07-25（等待产品与安全批准；**尚未实现**）

## 背景

V2 的 `user_id` 是只供协议、授权和持久化使用的不透明 UUID。当前密码
fallback 的 `account_handle` 仅是登录标识；它没有被定义为可公开查询的身份。
客户端因此只能让用户输入内部 UUID，并将房间 ID 的后缀作为会话标题。这不满足
常规聊天的私聊、加好友、拉群和群成员展示需求。

不能由客户端把本地备注、UUID 或登录标识伪装成公开昵称：这样会造成跨设备不一致，
也会把认证凭据/账号枚举策略意外变成产品协议。电话、邮箱、通讯录和模糊搜索还会
引入额外的同意、发现、反枚举、地区合规及删除规则，不能在没有决定时加入。

## 待批准的决策

以下选项互斥；在批准前，`user_id` 和 `account_handle` 均不得以“联系人名”形式
暴露给产品 UI 或目录 API。

| 选项 | 身份与发现 | 安全/产品后果 |
| --- | --- | --- |
| A（建议） | 独立的公开 `@handle`，精确匹配查询；另有可修改显示名。登录 handle 与公开 handle 不复用。 | 能支持常规私聊、好友与拉群，同时不扩大密码登录标识暴露面。目录必须限流、无前缀/模糊搜索且不泄露屏蔽/隐私原因。 |
| B | 复用当前 password `account_handle` 作为公开 `@handle`。 | 实现较少，但把登录标识变成可发现数据，增加凭据填充、钓鱼和账户枚举风险；仅在安全策略明确接受后可选。 |
| C | 无公开目录；通过已认证好友、一次性 QR/邀请或人工交换的联系人码建立关系。 | 隐私面最小，但首次私聊/拉群体验需要额外邀请流程，不能保留当前 UUID 输入作为最终产品 UI。 |
| D | 手机号、邮箱或通讯录发现。 | 需要单独的验证、哈希匹配、用户同意、可见性、删除、反枚举、地区合规和滥用处理 ADR；不属于本 ADR 的默认范围。 |

## A 方案获批后的不变量

这些不变量是建议方案的实施前提，不代表已接受实现：

- `user_id` 永不变且只用于内部授权/持久化；公开 handle 和显示名均不能替代它。
- 登录凭据和公开身份分表保存。密码 verifier、Passkey credential、refresh
  credential、电话或邮箱不能写入公开身份投影、群事件、Push、日志或指标。
- handle 仅支持精确、规范化查询；不得提供前缀、模糊、批量或未认证查询。请求
  需认证、限流、最小响应、`no-store`，且“未找到、不可发现、被屏蔽、无权查看”
  使用同一外部可见结果。
- 只有满足已批准的可见性策略的用户才能收到 profile projection。群成员可见的
  显示名、好友可见性、陌生人是否可按 handle 发现，必须作为明确的服务端策略，
  不能由 App 缓存决定。
- 显示名与 handle 都有 UTF-8 长度、Unicode 规范化、保留词、变更频率、历史
  保留与删除/复用规则；所有冲突检查和变更事件必须幂等、权威且可同步。

## 影响范围与实施门槛

批准后需要作为一个完整纵向能力交付，而不是仅替换 SwiftUI 文案：

1. 新增 V2 SQL migration：公开 profile、handle 唯一约束、变更操作与授权可见性
   事实；禁止从 password credential 表读取公开目录数据。
2. 新增 Core 身份类型、协议命令/事件、服务端目录与 profile 服务、错误模型和
   低基数审计/指标；目录必须在账号服务或专用身份服务的受认证 HTTPS 边界内。
3. 将允许的身份快照/增量同步进 ClientKit SQLite 投影；断网和 snapshot reset 后
   的展示不能依赖临时网络结果或 UserDefaults。
4. 替换 iOS 的 UUID 输入与 room-ID 标题：私聊、好友、群成员及会话列表只显示
   已授权的 profile 投影；用户操作通过公开 handle/联系人码解析到内部 ID。
5. 覆盖规范化冲突、重放、并发抢注、屏蔽/不可发现、删除/改名、目录限流、离线
   重试、snapshot reset、隐私日志和真实账号服务 HTTPS 回归。

## 发布门槛

在此 ADR 被批准、实现并通过上述回归之前，V2 可以保留内部开发用的 UUID 路径，
但不得把当前 UI 宣称为已完成的常规聊天联系人体验。电话/邮箱/通讯录发现需另行
批准，不能作为本方案的隐含扩展。
