# ADR-003：原生 TLS TCP 与客户端发布平台

状态：待产品、客户端与安全负责人批准
日期：2026-07-23
所有者：客户端与平台负责人

## 背景与决定

V2 已实现原生 TLS TCP framing 和独立 `IMV2ClientKit`，不复用 V1 HTTP/WS
协议。首个可发布客户端的平台、最低系统版本、后台能力、证书链轮换和网络
降级策略尚未批准；因此只接受“原生 TLS TCP 是 V2 实时协议”的方向，不批准
任何平台发布承诺。

## 备选方案

- HTTP/WebSocket：降低接入成本，但与已实现的帧、连接背压和协议模型冲突；
- 平台专属协议：增加多端不一致与测试矩阵；
- 原生 TLS TCP：统一二进制 framing，保留平台网络层适配空间。

## 不变量与后果

- TLS 1.3、帧上限、Protobuf 嵌套深度、单连接 in-flight 上限和 idle timeout
  必须在绑定端口前显式配置；认证成功前不得执行领域命令。
- 首发版本不协商 payload compression；客户端与服务端必须在 protobuf 解码前
  拒绝所有非零 frame flags。日后启用压缩需要独立协商字段、压缩/解压上限与
  比率限制、双端 golden vectors 以及本 ADR 的复审。
- 平台发布前必须明确 iOS/macOS 的 deployment target、后台网络行为、证书
  pinning/轮换策略、网络代理与弱网测试范围。
- V2 绿地发布不兼容 V1，详见 ADR-000；一旦外部分发，协议演进须另行评审。

## 落地、回滚与复审

批准后补齐平台 CI、真机 TLS/后台测试和证书轮换 runbook。首次外部测试版、
新增平台或证书策略变化时复审本 ADR。
