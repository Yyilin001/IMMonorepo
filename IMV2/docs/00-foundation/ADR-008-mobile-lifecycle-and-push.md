# ADR-008：移动生命周期、账号变化流与离线提醒

状态：账号变化流实施中；APNs alert 预留，真实投递按用户要求暂缓。
更新：2026-11-05

## 决定

房间唯一 Actor 仍然负责权限、消息接受和房间顺序。接受事务同时保存房间事件与
`room_dispatch_outbox`；只有事务提交后才返回接受结果。提交后的有界 Worker 按事件
所属成员修订枚举历史受众，把 `room_head` 写入各账号的个人同步流，并原子保存通知
待办。正文仍从权威房间日志按序拉取，账号头不授予权限、不推进正文游标。

物理连接、账号同步、正在查看的房间订阅是三个独立生命周期。重新认证只建立固定
账号会话，账号 Ready 不扫描全部房间、不安装全部 Owner 订阅。进入详情页才申请
该房间的实时订阅；离开页面或物理连接关闭时释放。App 经常进入后台不再引发
1000 房间全量 Owner 安装。

客户端普通重连保留同账号、同安装的目录扫描进度及完成态，只更换在途响应围栏。
个人增量记录与本地房间补读任务在同一 SQLite 事务保存。快照激活、目录拓扑失效和
定期完整性核对会重新扫描权威目录；其他情况下只恢复变化会话。消息持久游标、
恢复任务、最新可见摘要分别校验，不能用摘要或网络连接状态冒充已完成同步。

## 通知与数据同步

用户长期离线时，通知责任不能依赖在线设备或房间订阅。通知是提醒用户的独立路径，
正确的消息恢复仍由持久同步日志保证。未来可见提醒使用 APNs alert；静默
`content-available` 仅是机会性的同步优化，不能承诺唤醒或通知展示。

本轮用户明确要求先不接 APNs，只预留。`V2AccountNotificationDelivering` 是预留的
投递边界；Gateway 目前不注入实现，通知 Worker 只清理过期项。待办保留 24 小时，
未配置不能记为已投递，不查询设备、不消耗设备预算、不创建网络重试循环。过期不
影响个人同步日志、房间日志或其持久回执。源重放不能重新创建已完成的同一通知。

旧 mention-only 意图、relay 和对应表移除。普通消息与提及共用新责任路径；提及是
待办中的事实，未来策略决定是否提醒。现有通用后台 wake 的端点、加密、预算与
APNs 适配器保留为独立能力，配置其凭据不会启用新的可见提醒。

## APNs 接入时尚须完成

- 将账号待办转为幂等的设备投递计划；按当前成员状态、账号撤销、已读、静音或仅提及
  偏好检查资格。不能因为某一台设备在线就永久抑制其他设备。
- 设备绑定与登录会话有效期分开定义；明确注销撤销绑定，端点轮换使用 generation
  围栏。长期未打开 App 的设备策略不能简单等同于登录凭据过期。
- 限流和合并、提醒载荷与点击跳转、通知权限、隐私及 APNs 失败处理。
- 真机 APNs 展示及离线/注销/多设备验证。APNs 接受响应不等于设备展示，网络边界
  重试允许重复，不能声称端到端 exactly-once。

验证进度见 [改造记录](account-notification-redesign.md)。
