# ADR-017：公共消息以房间日志作为可靠恢复源

状态：已接受并实施；当前协议与全新数据库的公共消息恢复模型。

## 决定

私聊、标准群和大群的公共内容均按房间游标恢复，不再有
`planner`、`preplanned` 或逐成员公共消息持久投递的部署开关。
个人事件流仍承载成员关系、偏好、已读与单侧提示等个人状态。

房间日志是逻辑上按 `room_sequence` 排序的事件流，不要求所有事件都占用
`room_events` 中的一行。普通接受消息可以由带接受事件身份、提交时成员版本和
房间序号的 `messages` 行承载；其他需要独立事件行的内容由 `room_events`
承载。读取时合并两者，客户端在同一 SQLite 事务中物化事件和游标。

发送、编辑、撤回和 reaction 均依赖当前授权与消息接受时的不可变事实。
接受结果和可恢复事实在同一 PostgreSQL 事务内提交，成功 ACK 不能先于提交；
重复操作返回原结果。房间读取按当前资格及事件与原消息的历史可见性过滤。
无权事件可被扫描但不返回给客户端；continuation 表示已认证扫描到的序号。
完整编辑载荷使客户端能够跨越合法的版本缺口而不接收无权版本。

在线 NATS 房间提示只推动拉取；提示丢失、重复或 broker 不可用时，
PostgreSQL 持久事实、房间目录与游标仍支持恢复。

## 当前边界

- 新环境仅从当前 [canonical schema](../../sql/schema.sql) 建库；旧模式开关和旧投递表不参与部署或回退。
- 内容版本、成员变更和媒体读取各自仍须遵守提交时可见性与当前授权；详见
  [消息变更读取合同](../../../docs/reviews/message-mutation-read-contract.md)及
  [内容引用授权合同](../../../docs/reviews/message-reference-visibility-contract.md)。
- 客户端会话恢复的多设备、后台及长稳态验收仍以
  [当前验收矩阵](../../../docs/reviews/client-owned-conversation-sync-acceptance.md)为准；
  房间日志改造完成不代表这些组合已经通过。
- 部署回滚只能在当前协议和当前 schema 能力范围内进行；
  不允许重新打开已删除的逐用户公共消息投递路径。

## 验证

对私聊、标准群和大群分别核对：提交后丢 ACK 的幂等重放、消息行与事件行
合并读取、编辑/撤回/reaction 的授权和乱序恢复、无权尾部 continuation、
断线/提示丢失后的游标追赶，以及重启后是否仍只有一个接受效果。
容量报告必须固定代码版本、负载与客户端拉取模型；只测发送 ACK 或在线提示的
历史结果不能证明当前完整聊天链路的容量。现有证据与限制见
[实现状态](../implementation-status.md)和[房间日志实施记录](../../../docs/reviews/room-log-only-implementation.md)。
