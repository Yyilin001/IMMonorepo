# 常驻附件扫描

启用真实资源存储时，在部署 Compose 文件后叠加本目录的 compose.yml。绑定路径以第一个 Compose 文件所在的 IMV2 目录为基准。账号服务和网关使用相同的扫描策略，包括普通上传和转发导入。

- 将 IM_V2_CLAMD_SIGNATURE_DIRECTORY 指向由现有 freshclam 更新任务维护的官方病毒库目录。设置 IM_V2_CLAMD_SOCKET_DIRECTORY 为专用目录，所有者 UID 100、GID 101，模式 0770。服务端容器需要访问其中的 socket。仅守护进程挂载病毒库，两个调用端只读挂载 socket 目录、配置和客户端。
- 先启动 clamd 并等待就绪，再启动账号和网关。守护进程无网络接口，客户端把校验过 SHA-256 的临时文件流送入 Unix socket。每次读取实际已加载的签名日期，超过 48 小时或响应无效会返回扫描服务不可用。调用端的超时、取消、租约及临时文件清理继续由资源工作队列负责。
- 客户端实现现有资源工作进程使用的有限命令行协议；不启动 clamscan。配置中最大单文件和流大小均须与上传上限匹配。仓库示例为 256 MiB，本次测试环境沿用原上限 50 MiB，压缩展开扫描总量上限为 512 MiB。调整单文件上限时同时修改 clamd.conf 和两个服务的 IM_V2_RESOURCE_MAXIMUM_BYTES，并重建守护进程和调用端。
- clamd 每 60 秒检查病毒库，两个扫描线程，禁止并行重载两份引擎。更新时扫描可能等待，暂时失败由资源工作队列重试。先用正常样本及 EICAR 验证，再确认图片预览和消息 ACK。只有明确干净的结果可以继续处理，命中、超时、不可用及无效响应均不能放行。
- 账号容器不再为每张图加载病毒库，但守护进程空闲时仍持有引擎。容量评估应同时统计 clamd、账号容器和网关，覆盖病毒库重载以及并发上传。

测试部署可在账号服务和网关上显式设置 `IM_V2_RESOURCE_SCANNER=disabled`，同时移除 clamd 依赖并停止守护进程。此模式只校验对象身份、长度与 SHA-256，处理回执标记为 `integrity-only-v1`；文件不会经过病毒检测。恢复扫描时对两个服务重新应用上述常驻配置。
